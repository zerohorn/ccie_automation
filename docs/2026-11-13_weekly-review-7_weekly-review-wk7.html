Mental snapshot

  • Genie parse is one command → one dict. Genie learn is one feature → many commands → an Ops object whose data lives in .info. Pick parse when the task names a command; pick learn when it names a feature.
  • Genie diff is noisy by design unless the default exclusions (counters, timers) stay on. --exclude adds keys; --no-default-exclusion removes the defaults.
  • Vault KV v2 puts a hidden data/ segment in every read/write path and metadata/ in list/metadata paths. Most 403s on a "correct" policy come from this.
  • AppRole is a username/password pair for machines: role_id is not secret, secret_id is. Deliver the second one wrapped and single-use.
  • Terraform state is the binding between config addresses and real objects. state rm forgets, it never destroys; the import block re-binds; -refresh-only accepts drift.
  • AEtest verdicts come from exceptions: AssertionError = Failed, any other exception = Errored, a failed setup blocks every test in its testcase. Rollup takes the worst result.
  • The common thread this week: observe state, compare to intent, produce a verdict. Genie observes, Terraform compares, AEtest judges, Vault keeps the credentials out of all three.

Where this week fits

Read the figure left to right as one change window. Secrets come out of Vault, a provisioning tool pushes intent, Genie snapshots the device before and after, and AEtest turns the comparison into a pass/fail record that CI can gate on.

The week in three layers

L1 · Concept: four tools, one question

Each of this week's tools answers "what is the real state, and does it match what I wanted?" from a different side. Genie reads device state into Python structures. Terraform keeps its own record of real objects (state) and compares that record and the live API to the config. AEtest wraps checks in a result model so a script produces a verdict instead of a log. Vault sits underneath all of them so none of the three needs a password in a file.

L2 · Mechanics that trip people up

Genie. genie parse without --output prints JSON to the screen and leaves you nothing to diff. With --output DIR it writes <device>_<command>_parsed.txt plus a _console.txt with the raw output. genie learn writes <feature>_<os>_<device>_ops.txt, a _console.txt, and an _exception.txt only when the feature failed; "Feature not yet developed for this os" means no Ops model exists for that OS, so fall back to parsing commands. genie diff pulls default exclusions from verification_datafile.yaml for parse output and pts_datafile.yaml for learn output. The diff page shows two different paths for the pts file, so check which exists in your venv. File pairing between the two directories is by identical filename in the examples (inferred, not stated).

Vault. The CLI hides the KV v2 data/ segment: vault kv get -mount=secret app calls secret/data/app. A policy written for secret/app therefore never matches. List and metadata go to secret/metadata/…. In policies, * is a prefix glob allowed only as the last character, + matches one path segment, and deny beats everything including sudo. For AppRole, secret_id_num_uses defaults to 0 (unlimited); the best-practices page recommends 1. Response wrapping parks the real response in the cubbyhole of a single-use token whose TTL you set with X-Vault-Wrap-TTL or -wrap-ttl.

Terraform. Data sources are read during plan unless an argument depends on something only known at apply, or the data block depends on a managed resource that changes in this plan; then the read is deferred and the plan says so. depends_on on a data block makes Terraform wait until that dependency's operations finish, which in practice defers the read whenever the dependency has pending changes. state rm removes the binding and keeps the object; the next plan proposes creating it again. The import block needs to (an address with a matching resource block) and either id or identity, and the ID must be known at plan time. For ACI the ID is the full DN.

AEtest. A script is CommonSetup → Testcases → CommonCleanup. Each testcase may have one setup and one cleanup. If setup fails, every test in that testcase is Blocked. Inside a test, steps stop at the first non-Passed/Passx/Skipped step unless that step was started with continue_=True. Standalone runs (aetest.main()) print a summary and write no archive. Easypy (pyats run job) injects testbed from --testbed-file (or None without it) and writes TaskLog, reports and an archive.

L3 · Exam-depth detail

Task shapes consistent with this week's blueprint verbs: "gather" (3.3.b) asks for structured data from a named command or feature, often saved for comparison; "develop and execute" (3.3.c) asks for a runnable script or job with a defined verdict; "use a secret management system" (5.4) asks that a credential reach an application without living in code; "state management" (2.8.f) asks you to reconcile what Terraform thinks with what APIC has. These overlap at the edges: a gather task becomes a test when you add an assertion, and a Terraform reconcile becomes a test when you gate on the exit code.

Recall check (12)

Answer out loud before opening. Three per unit.

3.3.b Genie parse / learn / diff

Q1 What do parse and learn each return, and how many commands does each run?
AnswerParse runs one command and returns one structured dict. Learn takes a feature name, runs several commands, and returns an Ops object; the data is in .info.
Q2 genie parse "show version" printed JSON, and now you need files to diff later. What do you add, and what files appear?
Answer--output DIR. You get <device>_<command>_parsed.txt (structure), <device>_<command>_console.txt (raw output) and a connection_<device>.txt log. --raw stores output without parsing.
Q3 Where do genie diff's default exclusions come from for parse vs learn output, and which two flags change them?
AnswerParse: genie_yamls/<os>/verification_datafile.yaml. Learn: pts_datafile.yaml (two paths shown on the page; check your venv). --exclude adds keys; --no-default-exclusion drops the defaults.

5.4 Vault secret management

Q4 An app token gets 403 reading secret/app on KV v2. What path does the policy need, and where does list go?
Answersecret/data/app for read/write; secret/metadata/app for list and metadata. KV v2 keeps 10 versions by default.
Q5 Which AppRole value is secret, what is the default for secret_id_num_uses, and what does the best-practices page recommend?
Answersecret_id is secret; role_id is not. Default is 0 (unlimited); recommended is 1, delivered wrapped by a trusted broker over a separate channel from the role_id.
Q6 An unwrap of a wrapped secret_id is refused. Two possible reasons and what you do.
AnswerAlready unwrapped (someone else read it, possible interception) or the wrap TTL expired. Alert and investigate with the audit log, revoke, and issue a new secret_id.

2.8.d-f Terraform retrieval, provision, state

Q7 After terraform state rm aci_tenant.prod, what happens on APIC and what does the next plan propose? What is the config-driven alternative?
AnswerThe tenant stays on APIC, unmanaged. The next plan proposes creating it. Alternative: a removed block with lifecycle { destroy = false }, which shows in the normal plan/apply.
Q8 Write the two arguments of an import block for an ACI VRF and state the ID constraint.
Answerto = aci_vrf.x (a matching resource block must exist) and id = "uni/tn-T/ctx-V" (full DN). The ID must be known at plan time. terraform plan -generate-config-out=file.tf can draft the resource block.
Q9 When is a data source read at apply instead of plan?
AnswerWhen an argument is only known at apply, or the data block depends (directly or via conditions) on a managed resource that changes in this plan. depends_on makes it wait for that dependency's operations.

3.3.c AEtest jobs and scripts

Q10 A testcase's setup raises AssertionError. What are its tests, and what does the testcase report?
AnswerTests are Blocked. Setup is Failed. Failed + Blocked rolls up to Failed.
Q11 Step 2 of 3 fails and no step uses continue_. What runs? What changes if step 2 had continue_=True?
AnswerStep 3 is skipped and the section ends Failed. With continue_=True on step 2, step 3 runs; the section still rolls up to Failed.
Q12 Standalone vs Easypy: how does the testbed reach the script, and which writes an archive?
AnswerStandalone: you load it yourself and pass it to aetest.main(testbed=...); summary to stdout, no archive. Easypy: pyats run job ... --testbed-file injects testbed (None if omitted) and writes TaskLog, reports and an archive.

Integration drill · pre/post change gate (~40 min)

Combines: 5.4 + 3.3.b + 3.3.c (core), 2.8.f (stretch).

Target: Cat8000V (lab 17.16) for pyATS/Genie; Vault 1.20 on HORNLAB01; DevNet sandbox APIC for the stretch. ⚠ Install pyATS on the workstation first (pyats[library]); the tracker lists it as absent.

Requirement

  1. Store the Cat8000V login under KV v2 at secret/lab/cat8kv (keys username, password). Create policy pyats-ro that can read only that secret, and an AppRole pyats with secret_id_num_uses=1.
  2. Log in with the AppRole using a wrapped secret_id, read the password, and export it for the run. The password must not appear in any file in the repo.
  3. Write gate.py (AEtest) with: CommonSetup that connects to cat8kv; testcase Snapshot that learns the interface feature and saves it under a directory named by a phase parameter (pre/post); testcase Compare (post phase only) that diffs pre vs post and fails if any interface's oper_status changed, with one step per interface and continue_=True.
  4. Run it through Easypy with a job file and a testbed file, once before and once after you shut a loopback.
  5. Stretch (2.8.f): in a separate CI-style job, run terraform plan -refresh-only -detailed-exitcode against the sandbox tenant and treat exit code 2 as "drift found".

Reference fields and paths

  • Vault API paths: secret/data/lab/cat8kv, secret/metadata/lab/cat8kv; AppRole params token_policies, secret_id_num_uses; wrap with -wrap-ttl.
  • Testbed password from environment: %ENV{CAT8KV_PASS} ⚠ unverified markup — test in lab.
  • Genie: Ops .info, after.diff(before); or CLI genie diff pre post.
  • Easypy: run(testscript=..., runtime=runtime, taskid=..., phase='pre').

Verification

  • vault token capabilities <token> secret/data/lab/cat8kv returns read only ⚠; a second unwrap of the same wrapping token is refused.
  • Pre run: all Passed (Compare skipped or not run in pre). Post run after shutdown on a loopback: Compare is Failed, with one failed step for that loopback and the other steps Passed.
  • pyats logs view --latest shows both runs in the archive.
  • grep -r CAT8KV in the repo finds only the env-var reference.
Hint

Decide the phase directory in the job file, not the script. Put the connect in CommonSetup so a dead device blocks the run early with a clear section result. In Compare, load the two snapshots, walk info per interface, and open one step per interface with continue_=True so a single change does not hide the others. For Vault, create the wrapped secret_id in one shell (the "broker") and unwrap in another (the "app").

Solution outline 
# broker side (admin token)
vault secrets enable -path=secret kv-v2            # skip if already enabled
vault kv put -mount=secret lab/cat8kv username=admin password='...'
vault policy write pyats-ro - <<'EOF'
path "secret/data/lab/cat8kv" { capabilities = ["read"] }
EOF
vault auth enable approle
vault write auth/approle/role/pyats token_policies=pyats-ro secret_id_num_uses=1
vault read -field=role_id auth/approle/role/pyats/role-id
vault write -wrap-ttl=120s -f auth/approle/role/pyats/secret-id   # hand wrapping_token over

# app side
SID=$(VAULT_TOKEN=<wrapping_token> vault unwrap -field=secret_id)            # ⚠
export VAULT_TOKEN=$(vault write -field=token auth/approle/login role_id=... secret_id=$SID)
export CAT8KV_PASS=$(vault kv get -mount=secret -field=password lab/cat8kv)

# gate.py (core of Compare)
@aetest.test
def oper_status(self, steps, pre, post):           # ⚠ pass loaded Ops/info as parameters
    for name, data in post['info'].items():        # ⚠ structure of saved ops file
        with steps.start(name, continue_=True):
            before = pre['info'].get(name, {}).get('oper_status')
            assert data.get('oper_status') == before, f'{before} -> {data.get("oper_status")}'

# job.py
def main(runtime):
    run(testscript='gate.py', runtime=runtime, taskid='gate', phase='post')

pyats run job job.py --testbed-file tb.yaml

# stretch
terraform plan -refresh-only -detailed-exitcode; rc=$?; [ $rc -eq 2 ] && echo DRIFT
