Mental snapshot

  • Telemetry frequency (3.5.c): IOS XE update-policy periodic is in centiseconds. 6000 = 60 s, minimum 100 = 1 s. NX-OS sample-interval is milliseconds; 0 means event-based.
  • Dial-out (3.5.d): receivers can't be edited in place; only the first valid receiver is used. Change = remove and recreate the subscription.
  • Security (3.5.e): dial-in, the device is the TLS server (gNMI gnxi secure-*). Dial-out, the collector is the server and the device checks its cert. The cert has to match how you address the peer (SAN IP vs DNS).
  • Kubernetes (4.3.a): Deployment owns ReplicaSets which own Pods. Selectors are immutable. Service routes by label selector, targetPort must match the container port. Secrets: env var vs volume behave differently.
  • Ansible connections (2.7.d): network_cli = SSH CLI, httpapi = HTTP(S) API plugin (RESTCONF), netconf = ncclient on 830. Defaults bite: httpapi use_ssl false and validate_certs true; network_cli timeout 30 s.
  • Common thread: a "config accepted" result is not "working". Verify the state on the device or target, every time.

Where this fits

3.5.c-d + 3.5.e: telemetry frequency, dial-out, TLS

L1 concept

A subscription says what (XPath/path), how often (period or on-change) and where (receiver). Dial-out means the device opens the connection to the collector. TLS wraps that stream, or the gNMI server port on dial-in.

L3 exam detail

  • The 17.5 MDT chapter lists TLS auth as a gRPC restriction and also as a 17.1.1 feature. Don't trust either reading blindly: test grpc-tls vs grpc_tls spelling on the lab device.
  • Device private key import: the guide's OpenSSL recipe needs a des3-encrypted key, imported with crypto pki import … pem terminal and a password.
  • Certificate checks: openssl s_client -connect plus -verify_hostname (DNS SAN or CN) or -verify_ip (SAN IP only).

Integration drill (~15 min): TLS dial-out subscription pushed by Ansible

Requirement. On Cat8000V, create a periodic subscription (60 s) to a TLS collector, pushed with netconf_config over a netconf connection, then prove it, and prove the collector cert fits.

  • Fields: Cisco-IOS-XE-mdt-cfg:mdt-config-data; period unit centiseconds. Target: Cat8000V. ⚠ element names/namespace unverified: check with pyang -f tree on the model.
  • Connection: ansible_connection=ansible.netcommon.netconf, port 830, set ansible_network_os explicitly.
  • Verify: show telemetry ietf subscription all shows Valid; openssl s_client -connect <collector>:<port> -verify_ip <collector-ip> succeeds; second playbook run reports changed=0 ⚠.
  • Bonus: run the collector as a Deployment + Service in the cluster, cert in a Secret mounted as a volume ⚠ cluster not built in lab.
Hint

Receivers can't be edited. For a receiver change, delete then create. The period is 6000, not 60.

Recall check (3 per topic; answers collapsed)

  1. (3.5.c-d) The guide example says update-policy periodic 6000. Interval, and smallest legal value?
    Answer60 s; 100 (1 s).
  2. (3.5.c-d) Two receivers on one subscription, first unreachable. What does the second get?
    AnswerPer the 17.5 guide only the first valid receiver is used, so the second can receive data. ⚠ test in lab.
  3. (3.5.c-d) N9Kv sample-interval 10000: how often, and what does 0 mean?
    AnswerEvery 10 s (ms unit); 0 = event-based.
  4. (4.3.a) You edit a Deployment's selector and apply. Result, and two ways forward?
    AnswerRejected, selector is immutable. Delete and recreate the Deployment (mind the Pods), or create a new Deployment with the new selector and shift traffic. ⚠ the exact error text is untested.
  5. (4.3.a) Service targetPort doesn't match the container port. Symptom, and how do you confirm endpoints still exist?
    AnswerConnection refused/timeouts while the Service exists; endpoints still populate because selection is by label. Check with kubectl get endpoints. ⚠
  6. (4.3.a) Three differences, Secret as env vars vs as a volume?
    AnswerEnv values are fixed at container start while volume files can update; volumes expose keys as files with a mode; env needs valid variable names. ⚠ refresh behavior to be confirmed.
  7. (2.7.d) httpapi task to Cat8000V fails to connect: which two vars first, defaults?
    Answeransible_httpapi_use_ssl (false), ansible_httpapi_validate_certs (true).
  8. (2.7.d) network_cli default become_method, and default command timeout?
    Answersudo (use enable for IOS); 30 s.
  9. (2.7.d) netconf connection: port, library, unset network_os?
    Answer830; ncclient on the controller; Ansible tries to guess, then falls back to default.
  10. (3.5.e) Dial-in vs dial-out: who is the TLS server?
    AnswerDial-in: the device (cert on its trustpoint). Dial-out: the collector.
  11. (3.5.e) What does gnxi secure-client-auth add, and the default ports?
    AnswerChecks the client certificate; 9339 secure, 50052 insecure.
  12. (3.5.e) Collector reached by IP but its cert only has a DNS SAN. What fails, which openssl option reproduces it?
    AnswerIP verification; -verify_ip matches SAN IP only (-verify_hostname covers DNS SAN or CN).
