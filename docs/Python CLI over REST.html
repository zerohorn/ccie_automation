Blueprint 2.2: a Python CLI that wraps a REST API

Domain 2 (weight ⚠ unverified)Tier 1 (gap)Unit 24 of 49~18 min readLab: Cat8000V RESTCONF

Mental snapshot

  • A CLI app is five thin layers: parse argv, resolve config and credentials, call the API, check status, render output. Each layer fails differently, so each gets its own exit code or message.
  • argparse is stdlib, so it runs on the workstation with nothing installed. It exits with status 2 on bad arguments by itself.
  • requests has no default timeout and no default retries. You add both, every time.
  • HTTP success is not r.json() success. A 204 has no body and a 500 can carry JSON. Check status first, parse second.
  • Data goes to stdout, diagnostics go to stderr, and the exit status tells a calling script what happened. That is what makes the tool pipeable.
  • Credentials come from environment variables or a prompt, never from a flag you type into shell history.
  • Paginated APIs (Meraki) hand you the next page in a Link header, and requests parses it into r.links.

Where this fits

The blueprint text is "Build/manage/operate a Python-based CLI app that uses a REST API." Verb: build and operate, so expect to write one and fix a broken one.

Fundamentals to exam depth

L1 · Concept

A CLI over a REST API translates a command line into HTTP and back. devcli get logging becomes a GET with headers, a timeout and credentials, and the response becomes text on stdout. Everything interesting is in the seams: what happens when argv is wrong, the device is unreachable, the certificate is self-signed, the server says 401, or the body is empty.

You already know the server side of this from RESTCONF. On IOS XE 17.5 the root is /restconf, the media types are application/yang-data+json and +xml, and the verbs map as GET read, PATCH update, PUT create or replace, POST create or invoke, DELETE remove (RESTCONF Protocol, 17.5). The client's job is to speak that correctly and report failures honestly.

L2 · Mechanics

Parsing

Build one parser with subcommands. add_subparsers(dest=..., required=True) makes the subcommand mandatory; required defaults to False, so without it a bare invocation parses fine and your dispatch crashes. set_defaults(func=handler) on each subparser lets you call args.func(args) with no if-chain (argparse reference). Invalid arguments print usage to stderr and exit with status 2 on their own. choices= is checked after type= conversion, and a type function that raises ArgumentTypeError, TypeError or ValueError becomes a clean usage error; other exceptions are not caught.

The tutorial covers the option shapes you need: positional versus optional, action="store_true" for flags, mutually exclusive groups for --quiet versus --verbose, and action="count" for -vvv. With count, set default=0, otherwise an unused option is None and the comparison raises TypeError (Argparse Tutorial).

Config and credentials

Resolve in a fixed order: flag, then environment variable, then prompt. Use getpass.getpass() for the prompt; it does not echo, and if echo-free input is unavailable it warns and reads from stdin (getpass, 3.13). Keep the password out of argv. Anything on the command line lands in shell history and the process list (general practice ⚠, not from a fetched page).

Calling the API

Use one requests.Session per run. It keeps headers, auth and cookies on the object and reuses the TCP connection; method-level arguments override session values for that call only (Requests: Advanced Usage). Three defaults bite:

  • No timeout. "If no timeout is specified explicitly, requests do not time out." Pass timeout=(connect, read). The read value is the gap between bytes, not a wall-clock limit.
  • No retries. Mount an HTTPAdapter with urllib3 Retry if you want them. Be careful with non-idempotent verbs.
  • Verification is on. A self-signed Cat8000V raises SSLError. Point verify= at a CA file, or set REQUESTS_CA_BUNDLE. verify=False disables checking and the docs warn it opens you to man-in-the-middle attacks.

Then the response (Requests: Quickstart). raise_for_status() raises HTTPError for 4xx and 5xx. r.json() raises requests.exceptions.JSONDecodeError on a 204 or invalid JSON, and a JSON body does not mean success, since servers can return error details as JSON with a 500. Order: status, then body.

Pagination and async tasks

Meraki paginates with perPage, startingAfter and endingBefore, and returns a Link header with first, prev, next and last relations (Meraki pagination). Requests parses that header into r.links, so following pages is r.links.get("next") until it is absent. Catalyst Center works differently: write calls return a taskId, you GET /api/v1/task/<id> and read isError; auth is a Basic POST to /dna/system/api/v1/auth/token and then an X-Auth-Token header on every call (API Quick Start, 3.1.6). A CLI for that API needs a --wait flag for the poll loop.

The exit-code map is the design. Write it before the code.

The packaging guide frames it the same way: argparse is in the standard library and covers most needs, click is the advanced option, and typer sits on top of click (Creating and packaging command-line tools). In click, options belong to the command that defines them, so they go after the subcommand name (Click: Commands and Groups). Under exam pressure, use the library that cannot be missing.

Exit status mechanics: sys.exit(0) or sys.exit() is success, an integer is the status, and a string is printed to stderr with status 1. finally blocks still run (sys, 3.13). Logging goes through logging; with no configuration, warnings and above already print to stderr via the last-resort handler, and basicConfig(level=...) sets the root level, which is WARNING by default (logging, 3.13). Map -v counts to levels and nothing else needs to change. For output, json.dumps(obj, indent=2, sort_keys=True) gives stable, readable text, and python -m json.tool validates what you printed (json, 3.13).

Two version notes. The argparse pages fetched are Python 3.15.2 docs and the pin is 3.13; everything used here is old API (add_subparsers(required=) arrived in 3.7), but prog defaults changed in 3.14, so help text may differ. Requests docs are 2.34.2; the workstation version is unknown.

Meraki-style pagination. Cat8000V RESTCONF has no such loop; the same skeleton just runs once.

# parser: required subcommand, dispatch by set_defaults
p = argparse.ArgumentParser(prog="devcli")
p.add_argument("-v", "--verbose", action="count", default=0)   # default=0, or None breaks comparisons
sub = p.add_subparsers(dest="cmd", required=True)              # required=True or args.func may not exist
g = sub.add_parser("get", help="GET a RESTCONF path")
g.add_argument("path")
g.add_argument("--format", choices=["json", "raw"], default="json")
g.set_defaults(func=cmd_get)
args = p.parse_args()                                          # bad input: usage on stderr, exit 2
# client: one Session, explicit timeout, status before body
s = requests.Session()
s.headers.update({"Accept": "application/yang-data+json"})    # media type per 17.5 RESTCONF guide
s.auth = (user, pw)                                            # basic auth, as the guide's examples use
r = s.get(f"https://{host}/restconf/data/{path}", timeout=(3.05, 27))
r.raise_for_status()                                           # HTTPError on 4xx/5xx
body = r.json() if r.content else None                         # 204 has no body ⚠ r.content check is my idiom
# entrypoint: map failure classes to exit codes, data to stdout, text to stderr
def main():
    try:
        args = build_parser().parse_args()
        return args.func(args)
    except requests.exceptions.HTTPError as e:
        print(f"HTTP error: {e}", file=sys.stderr); return 1
    except requests.exceptions.Timeout:
        print("timed out", file=sys.stderr); return 3
if __name__ == "__main__":
    sys.exit(main())

Micro-drill (about 10 minutes)

Target: Cat8000V (IOS XE 17.16), RESTCONF enabled with restconf and ip http secure-server. IOSv and IOSvL2 have no RESTCONF; do not use them.

Requirement: write devcli with two subcommands. get PATH prints the RESTCONF response as sorted, indented JSON on stdout. status prints just the HTTP status code. Host from --host or DEVCLI_HOST; user from --user or DEVCLI_USER; password from DEVCLI_PASS or a prompt. Exit codes: 0 success, 1 HTTP error, 2 usage, 3 timeout or TLS failure. Errors to stderr only.

Reference: URI https://HOST/restconf/data/Cisco-IOS-XE-native:native/logging/monitor/severity (example from the 17.5 guide; present on 17.16 ⚠). Header Accept: application/yang-data+json.

Verify:

  • devcli get Cisco-IOS-XE-native:native/logging/monitor/severity | python -m json.tool succeeds; echo $? is 0.
  • Wrong password: nothing on stdout, message on stderr, status 1.
  • Unroutable host: returns in under about 30 seconds with status 3.
  • No subcommand: usage, status 2.
  • Missing path on the device: status 1, not a traceback.
Hint

Build the parser first and test --help. Make one function call(args) that returns the Response, and have both handlers use it. Catch exceptions in main() only. Use requests.exceptions.Timeout and SSLError for the 3 case. ⚠ whether SSLError is a subclass of another exception you also catch: test in lab.

Solution (⚠ unverified — test in lab) 
import argparse, getpass, json, os, sys
import requests

def call(a):
    pw = os.environ.get("DEVCLI_PASS") or getpass.getpass("Password: ")
    s = requests.Session()
    s.headers.update({"Accept": "application/yang-data+json"})
    s.auth = (a.user, pw)
    url = f"https://{a.host}/restconf/data/{a.path}"
    return s.get(url, timeout=(3.05, 27), verify=a.verify)

def cmd_get(a):
    r = call(a); r.raise_for_status()
    print(json.dumps(r.json() if r.content else None, indent=2, sort_keys=True))
    return 0

def cmd_status(a):
    print(call(a).status_code); return 0

def parser():
    p = argparse.ArgumentParser(prog="devcli")
    p.add_argument("--host", default=os.environ.get("DEVCLI_HOST"))
    p.add_argument("--user", default=os.environ.get("DEVCLI_USER"))
    p.add_argument("--verify", default=True)   # pass a CA file path; lab shortcut: False is not parseable here
    sub = p.add_subparsers(dest="cmd", required=True)
    g = sub.add_parser("get"); g.add_argument("path"); g.set_defaults(func=cmd_get)
    st = sub.add_parser("status"); st.add_argument("path"); st.set_defaults(func=cmd_status)
    return p

def main():
    a = parser().parse_args()
    if not (a.host and a.user):
        print("host and user required", file=sys.stderr); return 2
    try:
        return a.func(a)
    except requests.exceptions.HTTPError as e:
        print(f"HTTP error: {e}", file=sys.stderr); return 1
    except (requests.exceptions.Timeout, requests.exceptions.SSLError) as e:
        print(f"transport error: {e}", file=sys.stderr); return 3

if __name__ == "__main__":
    sys.exit(main())

Recall check

Today

  1. Running your CLI with no arguments crashes with AttributeError on args.func. Why, and what is the fix?
    Answer

    add_subparsers defaults to required=False, so a bare run parses and no subparser set func. Pass required=True; argparse then prints usage and exits 2.

  2. A request hangs against a powered-off router. What is the library default and what do you pass?
    Answer

    No timeout by default. Pass timeout=, as one number or a (connect, read) tuple. The read value is time between bytes, not total time.

  3. A PATCH succeeds but your code raises JSONDecodeError. Why, and what order do you check things in?
    Answer

    RESTCONF returns 204 No Content for PUT, PATCH and DELETE, and r.json() raises on an empty body. Check status (raise_for_status), then check there is a body, then decode.

  4. Which stream carries data and which carries errors, and what exit statuses do argparse errors and sys.exit("msg") give?
    Answer

    Data to stdout, errors and logs to stderr. Argparse usage errors exit 2. sys.exit("msg") prints the string to stderr and exits 1.
