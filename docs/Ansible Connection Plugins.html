Ansible connection plugins: network_cli, httpapi, netconf

2026-10-21 (Wed)Blueprint 2.7.dDomain 2 (weight unverified)Tier 3~18 min readUnit 15 of 49

Mental snapshot

  • A connection plugin is only the transport from controller to device. Modules decide what to do; the connection decides how bytes get there.
  • Three network transports: ansible.netcommon.network_cli (CLI over SSH), ansible.netcommon.netconf (XML over SSH, ncclient), ansible.netcommon.httpapi (REST over HTTP/S).
  • For network gear, modules run on the controller, not on the device. The connection is held open by a persistent background process, so credentials live in inventory vars, not per task.
  • ansible_network_os picks the sub-plugin (cliconf/terminal for CLI, httpapi plugin for HTTP). Wrong or missing value is the most common failure.
  • Defaults that bite: httpapi use_ssl is false; persistent command timeout is 30 s; netconf port is 830; network_cli become is false.
  • Lab gap: workstation has cisco.aci only, no cisco.ios. You can exercise httpapi against APIC and netconf/httpapi against Cat8000V with netcommon modules, but IOS-specific CLI modules are not there.

Where this fits

Fundamentals to exam depth

L1: concept

Normal Ansible copies a Python module to the target over SSH and runs it there. Network devices cannot run Python, so the module runs on the controller and the connection plugin carries commands or API calls to the device. Because logging in over SSH or opening a TLS session for every task is slow, the connection is kept in a long-lived process and reused across tasks. This is why you set ansible_connection, ansible_network_os, ansible_user and ansible_password once in group_vars.

L2: mechanics

network_cli. Opens an interactive SSH shell and drives it like a person: the terminal plugin knows the prompt and error patterns, the cliconf plugin knows how to enter config mode and fetch the running config. ssh_type defaults to auto: ansible-pylibssh if installed, else paramiko. The docs mark paramiko as deprecated, with removal after 2028-02-01. host_key_checking defaults to true, and host_key_auto_add defaults to true. Enable mode is become: true plus become_method: enable; the plugin's own default become_method is sudo, so forgetting the method is a real error source.

netconf. Needs ncclient on the controller. Port default 830. Unlike the other two, network_os can be left out (it is auto-detected) but set it anyway to keep behavior predictable. The tracker maps this to Cat8000V.

httpapi. A generic HTTP client; the httpapi sub-plugin chosen by network_os supplies login, headers and response handling. Defaults: use_ssl: false (so port 80), validate_certs: true. For a lab device on 443 with a self-signed cert you need both overridden. For RESTCONF, the restconf httpapi plugin adds root_path (default /restconf, var ansible_httpapi_restconf_root). For APIC, the cisco.aci.aci httpapi plugin handles the controller login.

Anatomy

Patterns as shown in the Ansible docs (netcommon 8.7.1 pages; Ansible docs "latest"). Values in angle brackets are yours.

# CLI over SSH, privileged mode (platform page pattern)
ansible_connection: ansible.netcommon.network_cli
ansible_network_os: <platform os name>
ansible_user: <user>
ansible_password: <vault>
ansible_become: true
ansible_become_method: enable
ansible_become_password: <vault>
# NETCONF (platform page pattern, INI style)
ansible_connection=ansible.netcommon.netconf
ansible_network_os=<platform os name>
ansible_user=<user>
# HTTPAPI knobs from the connection plugin page
ansible_connection: ansible.netcommon.httpapi
ansible_network_os: <httpapi plugin name>
ansible_httpapi_use_ssl: true          # default false
ansible_httpapi_validate_certs: false  # default true
ansible_httpapi_port: 443              # default 80 or 443 by use_ssl
ansible_httpapi_restconf_root: /restconf   # restconf plugin only; this is the default
# Device side, IOS XE 17.5 guides
netconf-yang                       ! SSH 830, user priv 15, AAA default methods
restconf
ip http secure-server              ! HTTPS, root /restconf

Allow up to 90 s after netconf-yang for the interface to come up (17.5 guide). With netconf-yang feature candidate-datastore on, running is not writable over NETCONF; your netconf_config must commit via candidate.

Speed notes (offline on the workstation)

  • ansible-doc -t connection -l lists connection plugins; ansible-doc -t connection ansible.netcommon.httpapi prints every option and variable name. Valid -t types include connection, httpapi, cliconf and netconf; terminal is not in the list.
  • ansible-doc -t httpapi -l shows which network_os values have an httpapi plugin installed. ansible-doc -t cliconf -l does the same for CLI. This is how you learn what cisco.ios absence costs you.
  • ansible-galaxy collection list confirms netcommon and cisco.aci versions (lab: 8.4.0 and 2.12.0).
  • Device side: show netconf-yang sessions, show netconf-yang datastores, show platform software yang-management process; clear netconf-yang session for a stuck lock.

Recall check

Today

1. A httpapi task against Cat8000V fails with a connection or certificate error. Name the two connection vars you check first and their defaults.

ansible_httpapi_use_ssl (default false, so port 80) and ansible_httpapi_validate_certs (default true, fails on self-signed).

2. Which three settings does a network_cli task need to run a config command on an IOS device whose login lands in user mode, and what is the plugin's default become_method?

become: true, become_method: enable, and the enable password (ansible_become_password). Default become_method on the plugin is sudo.

3. Name the default port and the controller-side library for the netconf connection, and what happens if network_os is unset.

Port 830; ncclient; the plugin tries to auto-detect network_os and falls back to default.

4. A command works from the CLI in 45 s but the task fails at 30 s. Give the message and two places to raise the limit.

"command timeout triggered, timeout value is 30 secs". Set ansible_command_timeout as a task or group var, or command_timeout under [persistent_connection] (env ANSIBLE_PERSISTENT_COMMAND_TIMEOUT).

From history

5. (from 2026-10-13) update-policy periodic 30: what interval do you get, and what is the minimum on IOS XE 17.5?

Centiseconds, so 0.3 s; the minimum is 100 (1 s). Restated from earlier pages.

6. (from 2026-10-15) Why does restconf_config with defaults fail on the second run of a create, and what makes it repeatable?

Its method defaults to post, which fails when the resource exists. Use an idempotent method (put or patch). ⚠ reconstructed from earlier pages; the second setting asked about on 10-15 is not restated here.
