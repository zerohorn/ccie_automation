Mental snapshot

  • Two separate skills: placement (which of 22 precedence levels wins) and rendering (Jinja2 turning variables into text or JSON).
  • Role defaults/ sits near the bottom (only command-line settings like -u are lower). Role vars/ sits high, above play vars and every inventory source. Put the knob users should change in defaults/, never vars/.
  • Runtime-created values (register, set_fact, include_vars) outrank role vars/. Role and include params outrank those. Extra vars (-e) beat everything.
  • All templating runs on the control node. The device never sees Jinja2, only the rendered result.
  • ansible.builtin.template defaults to trim_blocks: true and lstrip_blocks: false. That default explains most “extra blank line / stray indent” bugs.
  • Core 2.19 tightened templating: non-boolean when is an error, {{ }} inside an expression is an error, and untrusted template strings are not rendered.
  • Lab trap: there is no cisco.ios collection on the workstation, so drills render text and send it through modules you do have (aci_*, restconf_config, netconf_*).

Where this fits

Fundamentals to exam depth

L1: Concept

A variable is a named piece of data. A template is text with placeholders. Ansible fills the placeholders with variable values using Jinja2, then hands the result to a module. A role bundles tasks, default values, templates and files so you can reuse the pattern with different inputs. See Roles for the layout: tasks/, handlers/, templates/, files/, vars/, defaults/, meta/. Each directory is optional, and main.yml is read by default in most of them.

Names may contain only letters, numbers and underscores, cannot start with a number, and cannot be a Python or playbook keyword. Avoid shadowing lookup, query, now, undef and the reserved magic names (hostvars, groups, environment and others). A leading underscore does not make a variable private.

Templating happens on the control node: Ansible sends each target only the data a task needs. You do not need Jinja2 on a router, and a router never evaluates your {{ }}. Template files must be UTF-8. Source: Templating (Jinja2).

L2: Mechanics

Precedence is a ladder, not a set of scopes. Ansible collects every definition of a name, then the highest rung wins. Inside one rung, the later definition wins. Role defaults rank 2 of 22, only above command-line values that are not variables. Inventory sources and group_vars/host_vars follow, then host facts, then play-level vars, vars_prompt and vars_files, then role vars, block vars and task vars. After those come runtime values, then params, then -e.

Getting values into a role. The roles: keyword takes vars: or inline parameters, and giving different parameters runs the role again. include_role and import_role accept vars: but not inline role parameters. Variables from a role’s vars/ and defaults/ are imported into play scope unless you switch that off with the public option on import_role or include_role. Before ansible-core 2.15, vars: under roles: leaked into play scope, and DEFAULT_PRIVATE_ROLE_VARS controls this.

Role dependencies go in meta/main.yml and run before the role that lists them. A duplicate dependency runs once unless its parameters, tags or when differ, or allow_duplicates: true is set.

Facts and magic variables. hostvars[host] reaches any host’s variables, but facts show up there only after they are gathered or cached, and play-level vars are not mapped into hostvars. inventory_hostname is the inventory name; group_names lists the host’s groups; ansible_play_hosts lists active hosts. Facts live under ansible_facts. See Discovering variables: facts and magic variables.

Rendering pipeline. The controller merges variables for the host, evaluates the Jinja2 expression, and passes plain data to the module.

L3: Exam detail

Types on the command line. -e key=value gives strings. For numbers, booleans, lists or dicts use JSON or YAML (-e '{"vlan": 20}') or -e @file.yml. Source: ansible-playbook and Using variables.

Combining data. Lists merge with + in set_fact. Dicts merge with the combine filter, where later arguments win and recursive merges nested dicts. hash_behaviour=merge changes how dictionaries from different sources combine, and include_vars has a per-task hash_behaviour (added in core 2.12). dict2items and items2dict convert between dicts and lists. See filters.

Missing values. default(x) covers undefined; default(x, true) also covers false and empty. default(omit) on a module option drops the option entirely, so the module’s own default applies. mandatory raises when undefined. In 2.19, values that resolve to omit are dropped as soon as loop items are templated, so a missing loop-item key needs | default(omit).

The template module. src is read on the controller, dest is on the target. trim_blocks defaults to true (removes the first newline after a block tag), lstrip_blocks defaults to false, newline_sequence defaults to \n, backup false, force true. validate runs a command against a temp file (%s) before the final copy; no pipes. Putting a date in the template makes the task report changed every run. A first-line #jinja2: header overrides Jinja2 settings per file. Source: ansible.builtin.template.

Validate inputs. A role can ship meta/argument_specs.yml with a top-level argument_specs block (type, required, default, choices, elements). Ansible inserts a validation task at the start of the role and fails on mismatch. Play-level validation (validate_argspec) arrived in 2.20 as a tech preview, so it is outside your 2.19 pin. See Play Argument Validation.

Network twist. cli_config is the platform-agnostic CLI push and its page names the network_cli connection. It works through the platform’s cliconf plugin, which on IOS comes from a collection that your workstation does not have. Use it as a reading exercise only. restconf_config takes path, content (JSON by default, XML via format) and method (default post), over ansible.netcommon.httpapi with ansible_network_os: ansible.netcommon.restconf.

⚠ Exam-shape reminder: tasks of this kind usually ask you to change a role so a value comes from the right place (inventory, defaults, extra vars) or so a rendered output matches a spec. Practise reading the rendered output, not just writing the template.

Anatomy

Short snippets pinned to the fetched docs. They are parts, not the drill solution.

1. Role layout and which rung each file occupies

roles/tenant_baseline/
├── defaults/main.yml        # rank 2: inputs with safe defaults
├── vars/main.yml            # rank 15: internal constants
├── templates/summary.txt.j2 # read by template on the controller
├── tasks/main.yml
└── meta/argument_specs.yml  # validated before tasks run

2. Same name, four places

# roles/tenant_baseline/defaults/main.yml
baseline_state: present            # rank 2
# group_vars/all.yml
baseline_state: absent             # rank 5 (beats defaults)
# play:  vars: { baseline_state: query }   # rank 12 (beats group_vars)
# CLI:   ansible-playbook site.yml -e baseline_state=present   # rank 22 (wins)

3. Optional field with default(omit)

- name: Ensure tenants
  cisco.aci.aci_tenant:
    tenant: "{{ item.name }}"
    description: "{{ item.descr | default(omit) }}"
    state: "{{ baseline_state }}"
  loop: "{{ baseline_tenants }}"
  delegate_to: localhost

aci_tenant parameters tenant, description, state (absent, present, query; default present), plus host, username, password, validate_certs with environment fallbacks such as ACI_HOST. Docs are cisco.aci 2.13.0; lab has 2.12.0.

4. Template whitespace under the module defaults

{# templates/summary.txt.j2 #}
{% for t in baseline_tenants %}
tenant {{ t.name }}
{% if t.descr is defined %}
  description {{ t.descr }}
{% endif %}
{% endfor %}

With trim_blocks true and non-indented block tags, the tag lines leave no blank lines. Indent the tags and you get stray leading spaces until lstrip_blocks: true.

5. Argument spec

# roles/tenant_baseline/meta/argument_specs.yml
argument_specs:
  main:
    options:
      baseline_state:
        type: str
        choices: [present, absent, query]
        default: present
      baseline_tenants:
        type: list
        elements: dict
        required: true

Speed notes

  • Resolve a host’s inventory variables: ansible-inventory --host h1 -y (add -i and --playbook-dir so group_vars/ and roles/ resolve). --graph --vars shows groups with variables. This does not show play vars, role vars or -e.
  • Resolve the final value as the task sees it: add a debug task with var: baseline_state and run with -e variants. The facts page shows debug with var: ansible_facts and ansible h -m ansible.builtin.setup for all facts.
  • Module syntax offline: ansible-doc ansible.builtin.template, ansible-doc -s ansible.builtin.template for a snippet, -l to list, -j for JSON. -t role and -t keyword are valid types per the CLI page (output not verified). ansible-doc.
  • Pre-flight: ansible-playbook --syntax-check, --list-tasks, --list-hosts, --check --diff, --start-at-task, --step.
  • Filter lookup: Ansible filter and test names are in Using filters online; offline, use ansible-doc -t filter -l ⚠ (not verified on the workstation).

Micro-drill (about 10 min)

Target: localhost for rendering; DevNet Sandbox APIC for the optional aci_tenant step. No IOS devices needed.

Requirement. Build role tenant_baseline that creates a list of tenants and writes a one-line-per-tenant summary file. Rules:

  • Input baseline_tenants is a list of dicts with name and optional descr.
  • baseline_state defaults to present, and the role must reject any value outside present, absent, query before any task runs.
  • A tenant without descr must not send an empty description.
  • The summary must have no blank lines and no leading spaces on tenant lines.
  • Prove that -e baseline_state=query overrides a group_vars value of absent.

Reference fields and paths. meta/argument_specs.yml keys type, choices, default, elements, required. Module cisco.aci.aci_tenant keys tenant, description, state. Module ansible.builtin.template keys src, dest, trim_blocks, lstrip_blocks.

Verify.

  • ansible-playbook site.yml --syntax-check passes.
  • Run with -e baseline_state=bogus: fails at the validation task, no tenant task runs.
  • --check --diff on the template task shows the exact summary text; cat -A on the output shows no trailing spaces.
  • Run with -e baseline_state=query and confirm every aci_tenant result is a query, whatever group_vars says.
Hint

Validation lives in meta/, not in tasks/. The missing-description case needs a filter argument, not a when. For the whitespace, check where your block tags start on the line.

Solution 
# meta/argument_specs.yml: options baseline_state (type str, choices, default present),
#   baseline_tenants (type list, elements dict, required true)
# tasks/main.yml
- name: Ensure tenants
  cisco.aci.aci_tenant:
    tenant: "{{ item.name }}"
    description: "{{ item.descr | default(omit) }}"
    state: "{{ baseline_state }}"
  loop: "{{ baseline_tenants }}"
  delegate_to: localhost

- name: Render summary
  ansible.builtin.template:
    src: summary.txt.j2
    dest: /tmp/tenant_summary.txt
    mode: "0644"
  delegate_to: localhost
# templates/summary.txt.j2
{% for t in baseline_tenants %}
tenant {{ t.name }}{{ ' - ' ~ t.descr if t.descr is defined else '' }}
{% endfor %}
# group_vars/all.yml: baseline_state: absent
# run: ansible-playbook site.yml -e baseline_state=query

Recall check

Questions 5 and 6 come from history entries 3-10 days old (2026-10-06 and 2026-10-07).

  1. A role has port: 80 in defaults/, port: 8080 in vars/, and group_vars sets 9090. Which value does the task see, and what happens with -e port=443, including the type?
    Answer

    8080 (role vars rank 15 beat group_vars 6-7 and defaults 2). With -e port=443 the task sees "443" as a string, since -e wins at rank 22 and key=value is a string.

  2. A task ran set_fact: mode=a, then a later include_role passes mode: b as a param. Which wins, and why?
    Answer

    b. Role and include_role params are rank 20, above registered vars and set_facts at 19.

  3. A template task output has a blank line after every {% for %} body and a leading space before interface lines. Name the module defaults involved and two fixes.
    Answer

    trim_blocks defaults true and lstrip_blocks defaults false. Block tags that are indented keep their leading whitespace. Fixes: set lstrip_blocks: true, or put block tags at column 0. Use --check --diff to see it.

  4. On core 2.19, when: interfaces (a list) fails. Give the message and two fixes.
    Answer

    Conditionals must have a boolean result. Fix with interfaces | length > 0 or interfaces is truthy. ALLOW_BROKEN_CONDITIONALS only downgrades the error to a warning.

  5. (from 2026-10-06) You change the receiver port on a live IOS XE subscription and the collector never sees the new port. Why, and what is the minimum correct sequence?
    Answer

    Receivers cannot be modified in place on IOS XE 17.5, so the existing receiver and subscription keep the old port. Remove the subscription, delete and recreate the receiver with the new port, then recreate the subscription. Restated from the 10-06 page; not re-verified today.

  6. (from 2026-10-07) An XPath filter returns success and empty data. List the two most likely causes and how you tell them apart.
    Answer

    (1) The path, key predicate or namespace prefix does not match anything in the model. (2) The path is valid but no such data exists on the device. Tell them apart by sending the same request with a broader path or no filter and checking whether the node appears. Restated from the 10-07 page; not re-verified today.
