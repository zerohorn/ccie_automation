Mental snapshot

  • A testbed file is YAML that describes devices, how to reach them, credentials, and optionally links. Everything in 3.3.b (Genie parsers) and 3.3.c (AEtest jobs) loads it first.
  • Top-level keys: testbed, devices, topology, and extends. Only devices with a connections block is needed to log in.
  • The device key is the hostname. The getting-started example comments that it must match the hostname in the device prompt.
  • os (ios, iosxe, nxos) says what the device runs. type is a free-form string and is the one the schema marks required.
  • Credentials resolve connection, then device, then testbed. A missing named credential falls back to default.
  • Markups (%ENV{}, %ASK{}, %ENC{}, %CLI{}) are replaced by the loader before objects exist. Quote anything containing %.
  • Check a file with pyats validate testbed FILE; add --connect to try real logins.

Where this fits

Fundamentals to exam depth

L1: concept

pyATS models a lab as objects: one Testbed holds Device objects, which hold interfaces and links (Everything is an Object ✅). You rarely build them by hand. The docs recommend a YAML file unless you must create topology on the fly (Creating Topology ✅). The loader (from pyats.topology import loader; loader.load('file.yaml')) reads the file and returns the testbed. Jobs take the same file with pyats run job jobfile.py --testbed-file FILE, and the argument can be a path or a URL.

If you are used to Ansible, think of it as inventory plus connection vars, but typed: the file declares what each device is (os, type) so that later libraries pick the right behavior for it. If you are used to Terraform, the closest comparison is a variables file whose markups resolve at load time, before any object exists.

L2: mechanics

The file has four top-level keys. testbed carries testbed-wide data: name, credentials, servers, custom values. If name is omitted the loader uses the file name with a CONFIG. prefix and .yaml suffix trimmed. devices holds one entry per device. topology declares interfaces and links per device; the schema marks it optional and 3.3.a does not need it to log in. extends merges other testbed files into this one.

Credentials come from the nearest level. A connection with its own credentials uses them; otherwise it uses the device's, then the testbed's. If a named credential (say enable) is not found, the lookup uses default when one exists. Fields with "password" in the name are stored as secret strings and cannot be printed directly. The older passwords block (tacacs, enable, line, linux) is still in the production schema, so you will see it in older files (Topology Schema ✅).

Connection names are arbitrary labels. The docs' examples use a, b, vty, and cli. A connection's ip may be a hostname; it is resolved when the file loads. Any key the schema does not define on a connection is passed to the connection class constructor. That is the hook for per-connection SSH behavior, which matters on IOSv (below).

On connect: device.connect() with no arguments makes a connection with alias default. connect(alias='console', via='a') opens the named path and exposes it as device.console, so one device can hold several sessions at once. Testbed.connect() connects to all devices in threads; vias maps a device name to a connection name, and extra keywords such as log_stdout=False go to every connection (Using Topology Objects ✅). connections: defaults: via: sets the default path; if unset, the connection class decides.

L3: exam detail

Markups are the exam-relevant trick because they keep secrets and per-run values out of the file. From the YAML File Markups ✅ page:

MarkupUseTrap
%ENV{NAME}Value from the shell environmentQuote it when it follows a colon
%CLI{flag, default=12}Value from a command-line argumentMissing argument gives an empty string; a flag with no value gives True
%ASK{prompt}Prompt at load timeBlocks unattended jobs
%ENC{...}Decode a stored secret; prefix=x picks alternate settingsNeeds the same key/representer in config that encoded it
%INTF{name}, %CALLABLE{}, %{self.x}Interface lookup, function result, reference to current deviceCallable runs once; no retry with another argument form
extends: other.yamlMerge another fileDocs do not state precedence when files overlap

Secrets: pyats secret ✅ has keygen, encode, and decode, driven by [secrets] string.key and string.representer in the pyATS config. The page itself does not show %ENC{} in a testbed, so connect the two from the markup page.

Anatomy

A two-device skeleton assembled from the schema and getting-started pages. Key names come from the docs; the IPs and secrets are placeholders.

testbed:
  name: anatomy_demo                 # optional; else file name
  credentials:
    default:                         # fallback for any named credential
      username: "%ENV{LAB_USER}"     # quote: value starts with %
      password: "%ENV{LAB_PASS}"
    enable:
      password: "%ASK{Enable password}"

devices:
  nx-1:                              # key = hostname in the prompt
    os: nxos                         # picks platform behavior
    type: switch                     # free-form, schema marks required
    connections:
      a:                             # name is yours
        protocol: telnet             # console-style path
        ip: 192.0.2.10
        port: 2001
      vty:
        protocol: ssh
        ip: 192.0.2.11
        credentials:                 # connection-level override
          default:
            username: ops
            password: "%ENC{...}"    # decoded by pyATS config key

Load and use:

from pyats.topology import loader
tb = loader.load('anatomy.yaml')
nx = tb.devices['nx-1']
nx.connect(alias='ssh1', via='vty')   # opens connection 'vty' as nx.ssh1
print(nx.ssh1.execute('show version'))

Speed notes

  • pyats validate testbed FILE lints syntax. --connect makes a best-effort login to each device. --no-lint skips linting (pyats validate ✅).
  • Offline schema lookup: python -c "from pyats.topology import Device; help(Device)" ⚠ not tested on the workstation. Whether the exam VM has the docs site offline is unknown.
  • pyats --help, pyats validate --help, pyats secret --help for flags.
  • Copy the docs' ios_testbed.yaml shape, then edit. Typing the structure from memory costs more than editing a skeleton.
  • Never type a password inline in a file you will save in a repo. Use %ENV or %ENC.

Micro-drill (about 10 min)

Requirement. Write lab.yaml for four CML devices: iosv-1 (IOSv), iosvl2-1 (IOSvL2), c8kv-1 (Cat8000V), n9kv-1 (N9Kv). Use SSH on port 22, one shared username and password from environment variables, and an enable password from the environment. All four must connect through one connection name cli, set as the default.

Reference fields. testbed.credentials.default.{username,password}, testbed.credentials.enable.password, devices.<name>.{os,type,connections}, connections.defaults.via, connections.cli.{protocol,ip}, markup %ENV{}.

Target. The four lab devices; management IPs are placeholders (10.0.0.11 to 10.0.0.14), replace with yours. ⚠ unverified addressing

Verify.

  • export LAB_USER=... LAB_PASS=... LAB_ENABLE=..., then pyats validate testbed lab.yaml shows no lint errors.
  • pyats validate testbed lab.yaml --connect reports each device reachable. Expect IOSv and IOSvL2 to fail until the SSH options are fixed.
  • In Python: tb = loader.load('lab.yaml'); print({n: d.os for n, d in tb.devices.items()}) prints the four os values.
  • tb.devices['c8kv-1'].connect(); print(tb.devices['c8kv-1'].execute('show version')) returns IOS XE output.
Hint

Repeat the same connections block per device, or use YAML anchors. Device keys must equal each device's configured hostname. For the two 15.x devices the connection needs extra SSH options; check what your OpenSSH client says with ssh -vv first.

Solution 
testbed:
  name: cml_lab
  credentials:
    default:
      username: "%ENV{LAB_USER}"
      password: "%ENV{LAB_PASS}"
    enable:
      password: "%ENV{LAB_ENABLE}"

devices:
  iosv-1:
    os: ios
    type: router
    connections:
      defaults:
        via: cli
      cli:
        protocol: ssh
        ip: 10.0.0.11
        ssh_options: "-o KexAlgorithms=+diffie-hellman-group14-sha1 -o HostKeyAlgorithms=+ssh-rsa"
  iosvl2-1:
    os: ios
    type: switch
    connections:
      defaults:
        via: cli
      cli:
        protocol: ssh
        ip: 10.0.0.12
        ssh_options: "-o KexAlgorithms=+diffie-hellman-group14-sha1 -o HostKeyAlgorithms=+ssh-rsa"
  c8kv-1:
    os: iosxe
    type: router
    connections:
      defaults:
        via: cli
      cli:
        protocol: ssh
        ip: 10.0.0.13
  n9kv-1:
    os: nxos
    type: switch
    connections:
      defaults:
        via: cli
      cli:
        protocol: ssh
        ip: 10.0.0.14

Recall check

Today

  1. A connection has no credentials, the device has none, and the testbed has only default. The task enters enable mode. Which credential does the lookup use, and in what order does it search?
    AnswerConnection, then device, then testbed; a missing named credential (enable) falls back to default if set.
  2. What alias does device.connect() give with no arguments, and how do you open a second session on the vty path as vty_1?
    AnswerAlias default. device.connect(alias='vty_1', via='vty'), then device.vty_1.execute(...).
  3. Name the markups that read the shell environment, prompt the user, and decode a stored secret. Why must you quote them after a colon?
    Answer%ENV{}, %ASK{}, %ENC{}. Unquoted % values break YAML parsing; the docs say to quote strings with %.
  4. What does pyats validate testbed FILE --connect do beyond linting, and which flag turns linting off?
    AnswerIt attempts device.connect() to each device, best effort. --no-lint skips linting.
