Ansible loop control and conditionals

Blueprint 2.7.a Loop control · 2.7.b Conditionals Domain 2.0 Infrastructure as Code, 30% Tier 3 (proficiency check) Read about 18 min Pins Ansible Core 2.19 · cisco.aci 2.12 · netcommon 8.4

Mental snapshot

  • loop turns one task into N iterations. Each iteration is a separate module call with its own item, and a when on that task is evaluated once per item.
  • register on a looped task does not hold one result. It holds a dict with a results list, one entry per item. Most "attribute not found" errors in loops are this.
  • loop_control is the exam toolbox: label, loop_var, index_var, pause, extended, break_when (2.18+, so present in 2.19).
  • when is a raw Jinja expression with no braces. It must produce a real boolean in 2.19; a quoted expression is a string and now errors.
  • import_* copies the condition onto every task at parse time. include_* gates only the include itself, decided at run time.
  • Your lab has no cisco.ios. Loop drills go against cisco.aci modules (APIC) and ansible.netcommon RESTCONF modules (Cat8000V).

Where this fits

Fundamentals to exam depth

L1 · Concept

A playbook task normally runs once per host. Two keywords change that. loop makes the task run once per list element on each host. when decides, per host (and per item if there is a loop), whether the task runs or is skipped. You already know the shape from Terraform: for_each is the loop, count = cond ? 1 : 0 is the conditional. The Ansible difference is that skipping and looping are runtime decisions made task by task, and their results are recorded in a registered variable you inspect later.

loop arrived in Ansible 2.5 as the simpler replacement for the family of with_* keywords. Both still work, but you cannot put loop and a with_* on one task. For the exam, write loop. Recognise with_items, with_dict, with_sequence when you read older code and know their equivalents: with_items becomes loop: "{{ items | flatten(levels=1) }}", with_dict becomes | dict2items, with_sequence becomes range(...) | list.

L2 · Mechanics

Read the flow below once and the rest of the page is detail. The loop expands first, then the condition is checked for each item, then a module call happens or a skip is recorded, and everything lands in results.

Conditionals: where the expression is evaluated

when is a Jinja2 expression written without {{ }}. A list of conditions is an implicit AND. Useful tests inside when: is defined / is undefined, is match (anchored at the start), is search (anywhere), is regex, is subset, is version('x','>='), is truthy / is falsy, and the task-result tests is failed, is changed, is skipped, is succeeded. There is also is contains, mainly for use with select and selectattr.

Combined with a loop, the condition runs separately per item, so when: item.state | default('present') == 'present' can skip some items and process others in one task. Combined with a block, the condition is inherited by every task in the block.

roles: at play levelParse time (treated as static imports)Every task in the role

L3 · Exam detail

Ansible Core 2.19 changed conditional evaluation. The porting guide states that conditionals must now produce a boolean. A bare string or a non-empty list that used to be treated as truthy now raises "Conditionals must have a boolean result". The fix is an explicit comparison such as inventory_hostname | length > 0. The classic self-inflicted case is wrapping the whole expression in quotes inside when or assert.that; the expression becomes a string. The temporary escape hatch is the ALLOW_BROKEN_CONDITIONALS setting, which downgrades errors to warnings. Do not rely on it.

Other 2.19 traps that show up in loops. range() can no longer be returned from a template directly, so loop: "{{ range(0, 5) }}" fails and | list fixes it. Omit placeholders no longer leak from loop items into the task, so write item.descr | default(omit) where you want an optional module argument. Undefined-variable detection is stricter: a failed_when that reads result.exists on a stat result must read result.stat.exists. Integer properties like started and finished on async_status results cannot be used as booleans; use is finished. Native Jinja mode is now always on, so a list passed through replace becomes a string; use map('replace', ...).

Version drift in the docs. The Ansible docs "latest" pages describe a release newer than 2.19 and mention register projections (_task.result) as new in 2.21. Ignore those. break_when (2.18) is fair game. The module pages show cisco.aci 2.13.0 and netcommon 8.6.2, while the workstation has 2.12.0 and 8.4.0; parameter names used below are stable across those, but run ansible-doc on the workstation before trusting any detail.

Loops with roles. A role that loops internally and is itself called in a loop will collide on item. Ansible detects a loop variable that is already in use and fails the task. Give the outer loop a loop_var. Put loops on include_role (dynamic). Combining loop with import_role is not something to depend on; treat it as unsupported ⚠ (the docs summary I fetched was inconsistent on this, test it).

Network-specific wrinkle. Network modules run on the control node, and connection is chosen per host with ansible_connection and ansible_network_os. For the Cat8000V, restconf_get needs ansible_connection: ansible.netcommon.httpapi and ansible_network_os: ansible.netcommon.restconf. The cisco.aci modules take host, username, password directly and are run with delegate_to: localhost, so a loop over tenants is a loop on the control node, not per network device. That is why 2.7.d (connection plugins) is a separate blueprint line.

Anatomy

Short patterns pinned to Core 2.19 and cisco.aci 2.12. These show shape, not the drill solution.

1. Loop with a clean console and a registered result

- name: Tenants from data
  cisco.aci.aci_tenant:
    host: "{{ apic_host }}"
    username: "{{ apic_user }}"
    password: "{{ apic_pass }}"
    validate_certs: false
    tenant: "{{ item.name }}"
    description: "{{ item.descr | default(omit) }}"
    state: "{{ item.state | default('present') }}"
  delegate_to: localhost
  loop: "{{ tenants }}"
  loop_control:
    label: "{{ item.name }}"
  register: tenant_out

tenant, description, state (present, absent, query), validate_certs are documented parameters of cisco.aci.aci_tenant.

2. Second loop over the registered results

- name: Say what changed
  ansible.builtin.debug:
    msg: "{{ item.item.name }} was changed"
  loop: "{{ tenant_out.results }}"
  loop_control:
    label: "{{ item.item.name }}"
  when: item is changed

Each results entry carries the original loop element under item, hence item.item. ⚠ unverified: the item.item nesting is standard behavior but not on the pages I fetched; confirm with -v.

3. Retry with until, then a conditional on the outcome

- name: Wait for RESTCONF on Cat8000V
  ansible.netcommon.restconf_get:
    path: /data/Cisco-IOS-XE-native:native/hostname
  register: r
  until: r is not failed
  retries: 5
  delay: 10

⚠ unverified: the module's own doc example uses a /config/ prefix in path. Check what prefix the netcommon RESTCONF plugin expects on 17.16 before relying on /data/. Defaults if you omit them: retries 3, delay 5.

4. Early exit and position awareness

loop: "{{ vlans }}"
loop_control:
  extended: true
  index_var: n
  break_when: item.vlan_id | int > 4000
when: not ansible_loop.last

Illustrative fragment, not a full task. ansible_loop.last needs extended: true. The int filter use is ⚠ unverified for your data types.

5. Import versus include for a gated file

- include_tasks: tenants.yml
  when: apic_host is defined       # evaluated once

- import_tasks: tenants.yml
  when: apic_host is defined       # copied to every task inside

Speed notes (offline on the workstation)

  • ansible-doc -l cisco.aci lists modules in a collection; ansible-doc -s cisco.aci.aci_tenant prints a playbook snippet; ansible-doc cisco.aci.aci_vrf shows parameters, choices and return keys. It reads the DOCUMENTATION strings from the installed collection, so it matches what is on the box.
  • ansible-doc -t keyword loop_control should give the keyword's help. ⚠ unverified that loop_control is in the keyword list on 2.19; try ansible-doc -t keyword -l first.
  • ansible-doc -t test -l and ansible-doc -t filter -l list tests and filters. -t connection -l lists connection plugins (useful for 2.7.d).
  • Use -j for JSON output when you want to pipe to jq.
  • When a conditional errors under 2.19, run ansible-playbook -vv first. The message shows the value and its type.
  • Habit worth building: put loop_control: label on every loop in a lab task. It shortens output and makes idempotency checks readable.

Micro-drill (about 10 minutes)

Target: DevNet Sandbox APIC, with cisco.aci on the workstation. Requirement: from one data structure, create or remove tenants, create VRFs only under tenants that should exist, and print a line for any tenant not found on the APIC. One playbook, three loops, no repeated tasks per tenant.

Data (tenants.yml):

tenants:
  - { name: T_PROD, vrfs: [PROD_VRF1, PROD_VRF2] }
  - { name: T_DEV,  vrfs: [DEV_VRF] }
  - { name: T_OLD,  state: absent }

Rules:

  • Console output for each loop shows only the tenant name (or tenant/VRF).
  • The VRF task must not run for a tenant whose state is absent.
  • Last task loops over the query results and prints only for tenants with an empty current.

Reference fields: cisco.aci.aci_tenant: tenant, state (present/absent/query), returns current. cisco.aci.aci_vrf: tenant, vrf, state. Auth: host, username, password, validate_certs. Sandbox address and credentials change; take them from the sandbox page and pass them as extra vars.

Verify:

  • First run shows changed for T_PROD, T_DEV and their VRFs; T_OLD is ok or changed depending on prior state.
  • Second run shows zero changed (idempotent).
  • Query loop prints a line for T_OLD only. ⚠ Assumes a query for a missing tenant returns an empty current; test in lab.
  • Cross-check in the APIC GUI under Tenants.
Hint
  • The VRF loop needs a parent and a child in one loop. Look at the subelements filter on the loops page's filter list. Parent is item.0, child is item.1.
  • T_OLD has no vrfs key. The filter has an option to tolerate that (⚠ skip_missing=True, check with ansible-doc -t filter -l then ansible-doc -t filter subelements).
  • Use default('present') when reading state.
Solution 
---
- hosts: localhost
  gather_facts: false
  vars_files: [tenants.yml]
  tasks:
    - name: Tenants
      cisco.aci.aci_tenant:
        host: "{{ apic_host }}"
        username: "{{ apic_user }}"
        password: "{{ apic_pass }}"
        validate_certs: false
        tenant: "{{ item.name }}"
        state: "{{ item.state | default('present') }}"
      loop: "{{ tenants }}"
      loop_control: { label: "{{ item.name }}" }

    - name: VRFs
      cisco.aci.aci_vrf:
        host: "{{ apic_host }}"
        username: "{{ apic_user }}"
        password: "{{ apic_pass }}"
        validate_certs: false
        tenant: "{{ item.0.name }}"
        vrf: "{{ item.1 }}"
        state: present
      loop: "{{ tenants | subelements('vrfs', skip_missing=True) }}"
      loop_control: { label: "{{ item.0.name }}/{{ item.1 }}" }
      when: item.0.state | default('present') == 'present'

    - name: Query
      cisco.aci.aci_tenant:
        host: "{{ apic_host }}"
        username: "{{ apic_user }}"
        password: "{{ apic_pass }}"
        validate_certs: false
        tenant: "{{ item.name }}"
        state: query
      loop: "{{ tenants }}"
      loop_control: { label: "{{ item.name }}" }
      register: q

    - name: Report missing
      ansible.builtin.debug:
        msg: "{{ item.item.name }} not on APIC"
      loop: "{{ q.results }}"
      loop_control: { label: "{{ item.item.name }}" }
      when: item.current | length == 0

Run: ansible-playbook drill.yml -e apic_host=... -e apic_user=... -e apic_pass=.... On the exam you would keep credentials out of the command line; this is a lab shortcut.

Recall check

History has no entries 3 to 10 days old yet, so questions 5 and 6 are an early review of 2026-09-28.

  1. A looped task is registered as r. The next task uses when: r.stdout is search('x') and fails with an undefined attribute. Why, and what structure fixes it?
    AnswerWith a loop, r holds a results list, one entry per item. Loop over r.results and read item.stdout; top-level skipped is true only when all iterations were skipped.
  2. In 2.19, what happens to when: 'inventory_hostname | length > 0', and how do you fix it?
    AnswerThe quotes make it a string, so it is not a boolean and 2.19 errors ("Conditionals must have a boolean result"). Remove the quotes and keep an explicit comparison.
  3. The first task in an imported file sets x; the import carries when: x is not defined. What happens to the remaining tasks, and what changes with include_tasks?
    AnswerImport copies the condition to each task and evaluates each separately, so later tasks skip once x exists. With include, the condition is checked once on the include; if it passes, inner tasks run.
  4. Which three loop_control settings hide everything but a name from the console, avoid collision in a nested include, and stop the loop on a condition?
    Answerlabel, loop_var, break_when (new in 2.18).
  5. (from 2026-09-28) What's the functional difference between a RESTCONF PATCH and a NETCONF edit-config against the candidate datastore, in terms of when the change takes effect?
    AnswerPATCH applies to the running configuration immediately. edit-config on candidate stages the change; nothing takes effect until a commit.
  6. (from 2026-09-28) A YANG list node appears in a RESTCONF JSON body and in a NETCONF XML body. How does its shape differ?
    AnswerJSON puts list entries in an array under the list name (module-qualified at the top). XML repeats the list element once per entry inside the parent with the module namespace.
