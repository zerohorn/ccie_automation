Read time: ~18 min
Unit: 32 of 49
Exam pins: Python 3.13 · cisco.aci 2.12 (for comparison)

Mental snapshot

  • APIC exposes one REST surface over the whole Management Information Tree (MIT). Every object has a class (fvTenant) and a unique DN (uni/tn-Prod).
  • Two read shapes: /api/mo/<dn>.json (one object, optionally its subtree) and /api/class/<class>.json (every instance of a class). The suffix, not the headers, decides JSON vs XML.
  • Only GET, POST and DELETE. POST both creates and updates; there is no PUT. Deletion is either DELETE or a POST with "status":"deleted".
  • Auth = POST aaaLogin → token → send it as a cookie on every call; aaaRefresh before the timeout (default 600 s; the login response tells you the real value in refreshTimeoutSeconds).
  • Responses always wrap results in imdata, a list of one-key dicts: {"<class>": {"attributes": {...}, "children": [...]}}.
  • Query knobs you must recognise on sight: query-target, target-subtree-class, query-target-filter, rsp-subtree, rsp-subtree-include, rsp-prop-include, page/page-size/order-by.
  • Python-wise this is plain requests: a Session to carry the cookie, explicit timeout, verify handled on purpose, and dict navigation through imdata.

Where this fits

L1 — Concept: the APIC is a database you talk to over HTTPS

Forget the CLI model. APIC holds the whole fabric as a tree of managed objects (MOs). The root is uni for the policy universe; tenants hang off it as tn-<name>, and everything you configure in a tenant (VRF, bridge domain, application profile, EPG, contract) is a child or grandchild. Each MO has a class name, which is its type, and a relative name (RN). Join the RNs from the root and you get the DN, the object's primary key. The Cisco guide states the rule plainly: a DN is a sequence of RNs, and you cannot rename an existing object. Renaming means delete and recreate, because the name is part of the key.

Two families of objects matter for scripting. Policy objects are things you configure (fvTenant, fvBD, fvAEPg). Relation objects start with Rs and link one policy to another by name: fvRsCtx under a BD points at a VRF through tnFvCtxName; fvRsBd under an EPG points at a BD through tnFvBDName; fvRsProv/fvRsCons point an EPG at a contract through tnVzBrCPName. If you know the Terraform provider, this is exactly why aci_rest_managed needs dn, class_name and content: those three fields are an MO.

Solid = containment (DN path). Dashed = relation by name (Rs* objects). RN prefixes marked ⚠ (BD-, ap-, epg-, ctx-) were not shown in today's fetched text; confirm with a GET in the sandbox before you hard-code them. tn- is confirmed.

L2 — Mechanics: URL, verbs, payloads, auth

URL grammar

The guide gives two forms: https://host/api/mo/<dn>.{json|xml}?options and https://host/api/class/<className>.{json|xml}?options. /api/node/mo and /api/node/class are interchangeable with these. Only HTTPS is on by default. Content-Type and Accept are ignored; the file-style suffix sets the encoding. That last point bites people coming from RESTCONF, where headers rule. The request body cap on api URIs is 1 MB.

Payload shape

JSON payloads mirror the tree: one top key = class; under it attributes (a dict of properties) and optionally children (a list of more one-key dicts). The guide adds two rules worth memorising: list attributes before children, and remember the API is case-sensitive. You can POST to the parent's DN with the child's name, or to the object's own DN; the guide shows both for a tenant (POST /api/mo/uni.xml with <fvTenant name="ExampleCorp"/>, and POST /api/mo/uni/tn-ExampleCorp.xml with the DN set). Posting a whole subtree in one call is normal and atomic from your script's point of view.

Authentication lifecycle

From the guide: aaaLogin takes an aaaUser with name and pwd; the token comes back both in the body and as a cookie. aaaRefresh (GET with no body) resets the timer and returns a new token, so a script that caches the first token and refreshes without storing the new one will break on the next call ⚠ (behaviour inferred from "token changes on each refresh"; test it). aaaLogout does not end the session immediately; it lapses when the refresh timeout passes. Default session timeout is 600 s; read refreshTimeoutSeconds from the login response instead of assuming. For RADIUS/TACACS login domains, prefix the user as apic:<domain>\<user>. aaaListDomains works without logging in.

There is an optional hardening mode: add ?gui-token-request=yes to the login URI, get a urlToken back, and send it on every request as a challenge query parameter or APIC-challenge header. Recognise it if a task hands you a script that "worked yesterday" and now returns errors after someone enabled challenge tokens.

Python side: why a Session

The Requests docs say a Session persists cookies across requests and reuses TCP connections via urllib3 pooling. APIC returns the token as a Set-Cookie, so a Session that did the login automatically carries the cookie on later calls; you don't have to rebuild a cookies= dict each time (the Cisco Live lab does it manually, which works too). Two traps from the same page: method-level parameters (for example a cookies= passed to one call) are not persisted on the session, and requests have no timeout unless you set one. Pass timeout=(connect, read) on every call; the guide's own figure is 90 s per query on the APIC side, so a read timeout shorter than that can cut off a large but legitimate query.

verify defaults to True; an untrusted cert raises SSLError. The sandbox and most labs use self-signed APIC certs, so you'll see verify=False plus urllib3.disable_warnings(InsecureRequestWarning) in Cisco's lab code. Requests' docs are blunt that verify=False accepts any certificate. In an exam script, prefer verify="/path/to/ca.pem" if a CA is provided; otherwise do what the task says and don't spend time on it.

Selection versus return is the mental split. query-target + target-subtree-class + query-target-filter decide which MOs match. rsp-* decide what you get back for each match. A task phrased "list every EPG in tenant Prod with its BD binding" wants subtree selection of fvAEPg plus rsp-subtree=children with rsp-subtree-class=fvRsBd ⚠ (combination not shown verbatim; verify in sandbox).

Errors and scale

The guide documents scale failures as HTTP 503 with "result dataset is too big" or "destination is not available", says queries can time out at 90 s, and recommends retrying timeouts 3–5 times and filtering when the set is too big. That gives you a clean troubleshooting order for a slow or failing class query: filter server-side, then page, then retry. The error body format itself (an error object with code and text inside imdata) was not in today's fetched text ⚠, so in a script, print r.status_code and r.text rather than assuming keys.

Distinguishing auth failures: an expired or missing cookie typically comes back as 403 with a token message ⚠ (not in today's sources). Practically, if a long-running script dies after ten minutes, you forgot aaaRefresh; if it dies immediately on the second call, you're not carrying the cookie (wrong cookie name, or a per-call cookies= you expected the session to remember).

Subscriptions (recognise, don't over-invest)

APIC can push changes: open a WebSocket at https://host/socket<token>, add ?subscription=yes to a query, get a subscriptionId, and refresh it with GET /api/subscriptionRefresh.json?id=<id> at least every 60 s. Stats objects don't generate notifications. Python's standard library has no WebSocket client, and nothing in the workstation tooling list names one ⚠, so treat this as read-and-recognise.

Anatomy — annotated snippets (Python 3.13, requests)

Patterns consistent with the Cisco guide and the Cisco Live lab code. Not the drill solution. Whole-script behaviour ⚠ unverified — run against the sandbox.

import os, requests
from urllib3.exceptions import InsecureRequestWarning
requests.packages.urllib3.disable_warnings(category=InsecureRequestWarning)  # lab only

APIC = os.environ["APIC_IP"]                      # creds from env, never in code (5.4/5.5)
s = requests.Session()                            # carries Set-Cookie token automatically
s.verify = False                                  # self-signed APIC; use a CA path if given
TO = (5, 90)                                      # connect, read — APIC query limit is 90 s

login = {"aaaUser": {"attributes": {"name": os.environ["APIC_USERNAME"],
                                    "pwd":  os.environ["APIC_PASSWORD"]}}}
r = s.post(f"https://{APIC}/api/aaaLogin.json", json=login, timeout=TO)
attrs = r.json()["imdata"][0]["aaaLogin"]["attributes"]
ttl = int(attrs["refreshTimeoutSeconds"])         # don't assume 600
# Class query with server-side filter; read attributes by class key
params = {"query-target-filter": 'eq(fvTenant.name,"Prod")'}
r = s.get(f"https://{APIC}/api/class/fvTenant.json", params=params, timeout=TO)
for mo in r.json()["imdata"]:
    print(mo["fvTenant"]["attributes"]["dn"])     # → uni/tn-Prod
# One POST, whole subtree: VRF + BD bound to it + subnet   (guide 4.0 example, JSON form ⚠)
bd = {"fvTenant": {"attributes": {"name": "Prod"}, "children": [
        {"fvCtx": {"attributes": {"name": "V1"}}},
        {"fvBD":  {"attributes": {"name": "BD1"}, "children": [
            {"fvRsCtx":  {"attributes": {"tnFvCtxName": "V1"}}},   # relation by NAME
            {"fvSubnet": {"attributes": {"ip": "10.10.100.1/24"}}}]}}]}}
r = s.post(f"https://{APIC}/api/mo/uni.json", json=bd, timeout=TO)
print(r.status_code, r.text)                      # success: empty imdata, totalCount "0"
# Delete inside a payload (status form) vs DELETE verb
s.post(f"https://{APIC}/api/mo/uni/tn-Prod.json",
       json={"fvTenant": {"attributes": {"name": "Prod", "status": "deleted"}}}, timeout=TO)
# or: s.delete(f"https://{APIC}/api/mo/uni/tn-Prod.json", timeout=TO)

Note on json= vs data=json.dumps(...): both send the same body; the Cisco Live lab uses data=. APIC ignores Content-Type anyway (guide), so either works.

Speed notes (offline on the workstation)

  • Requests API without internet: python3 -c "import requests; help(requests.Session.request)" lists timeout, verify, params, json ⚠ (assumes requests installed in the uv env; check uv pip list).
  • Payload shapes for free: the installed collection documents ACI classes. ansible-doc cisco.aci.aci_bd / aci_epg show parameters that map onto MO attributes; ansible-doc cisco.aci.aci_rest shows raw path/content examples ⚠ (module content at 2.12 not checked today).
  • Terraform schema: terraform providers schema -json | jq '.provider_schemas[].resource_schemas.aci_rest_managed' ⚠ reminds you of the dn/class_name/content triple.
  • Let APIC write the payload: in the GUI, the API Inspector (click "welcome, <name>" → Show API Inspector) logs the exact REST calls the GUI makes. Do the task once in the GUI, copy URL + body, parametrize in Python.
  • Re-POSTable read: GET the object with rsp-subtree=full&rsp-prop-include=config-only, strip dn/status if needed, and you have a template.
  • Quick JSON look: python3 -m json.tool on a saved response.

Micro-drill (~10 min) — "Ensure tenant baseline"

Target: DevNet Sandbox APIC (ACI Simulator Always On). Use your own tenant name (e.g. mh-drill) — shared sandbox.

Requirement: Write aci_baseline.py that (1) logs in using env vars, (2) creates tenant mh-drill with VRF V1, BD BD1 bound to V1 with subnet 10.99.0.1/24, AP App, EPG Web bound to BD1 — in a single POST, (3) reads back every EPG in the tenant and prints name → BD, (4) exits non-zero if the binding is missing, (5) never hangs on an unreachable APIC.

Reference names: aaaLogin, aaaUser.attributes.name/pwd, fvTenant, fvCtx, fvBD, fvRsCtx.tnFvCtxName, fvSubnet.ip, fvAp, fvAEPg, fvRsBd.tnFvBDName, query-target=subtree, target-subtree-class, rsp-subtree=children, rsp-subtree-class.

Verify: run twice — second run must also succeed (POST is create-or-update). Then GUI → Tenants → mh-drill → EPG Web shows BD1. Then point APIC_IP at a dead IP: script must fail within your connect timeout. Finally DELETE uni/tn-mh-drill.

Hint

Nest fvAp → fvAEPg → fvRsBd as children of the same fvTenant you use for VRF/BD. For the read-back, query the tenant DN with subtree selection of fvAEPg and ask for children of class fvRsBd; the BD name is in the relation's tnFvBDName. Wrap everything in one Session and pass timeout= every time.

Solution (⚠ not executed against the sandbox today) 
#!/usr/bin/env python3
import os, sys, requests
from urllib3.exceptions import InsecureRequestWarning
requests.packages.urllib3.disable_warnings(category=InsecureRequestWarning)

APIC, T = os.environ["APIC_IP"], "mh-drill"
TO = (5, 90)
base = f"https://{APIC}/api"
s = requests.Session(); s.verify = False

def login():
    body = {"aaaUser": {"attributes": {"name": os.environ["APIC_USERNAME"],
                                       "pwd": os.environ["APIC_PASSWORD"]}}}
    r = s.post(f"{base}/aaaLogin.json", json=body, timeout=TO)
    if r.status_code != 200:
        sys.exit(f"login failed {r.status_code}: {r.text}")

def rel(cls, **a): return {cls: {"attributes": a}}

payload = {"fvTenant": {"attributes": {"name": T}, "children": [
    rel("fvCtx", name="V1"),
    {"fvBD": {"attributes": {"name": "BD1"}, "children": [
        rel("fvRsCtx", tnFvCtxName="V1"),
        rel("fvSubnet", ip="10.99.0.1/24")]}},
    {"fvAp": {"attributes": {"name": "App"}, "children": [
        {"fvAEPg": {"attributes": {"name": "Web"}, "children": [
            rel("fvRsBd", tnFvBDName="BD1")]}}]}}]}}

try:
    login()
    r = s.post(f"{base}/mo/uni.json", json=payload, timeout=TO)
    if r.status_code != 200:
        sys.exit(f"POST failed {r.status_code}: {r.text}")
    q = {"query-target": "subtree", "target-subtree-class": "fvAEPg",
         "rsp-subtree": "children", "rsp-subtree-class": "fvRsBd"}
    r = s.get(f"{base}/mo/uni/tn-{T}.json", params=q, timeout=TO)
    ok = True
    for mo in r.json()["imdata"]:
        epg = mo["fvAEPg"]
        bds = [c["fvRsBd"]["attributes"]["tnFvBDName"]
               for c in epg.get("children", []) if "fvRsBd" in c]
        print(f'{epg["attributes"]["name"]} -> {bds[0] if bds else "MISSING"}')
        ok &= bool(bds and bds[0])
    sys.exit(0 if ok else 2)
except requests.exceptions.RequestException as e:
    sys.exit(f"APIC unreachable/timeout: {e}")

Recall check

  1. Name the three APIC session endpoints, what each takes, and the one detail about aaaRefresh that breaks naive token caching.
    AnsweraaaLogin (POST aaaUser name+pwd → token + cookie), aaaRefresh (GET no body, or POST login body → resets timer), aaaLogout (POST aaaUser name; session lapses after timeout). The token changes on every refresh, so store the new one. Default timeout 600 s; read refreshTimeoutSeconds.
  2. You need every EPG in tenant Prod. Write the URL two different ways and say which one the guide's 503 advice prefers for a big fabric.
    Answer/api/mo/uni/tn-Prod.json?query-target=subtree&target-subtree-class=fvAEPg (DN-scoped) or /api/class/fvAEPg.json?query-target-filter=wcard(fvAEPg.dn,"tn-Prod/") ⚠ syntax. Scoping to a DN / filtering is what the guide recommends over a broad class query.
  3. Which HTTP verbs does APIC accept, how do you delete an object without the DELETE verb, and why can't you rename a BD with a POST?
    AnswerGET, POST, DELETE only (no PUT). POST the object with "status":"deleted". The name is part of the RN/DN (primary key); the guide says you cannot rename an existing object — delete and recreate.
  4. Selection vs return: which parameters decide what matches, and which decide what's returned under each match?
    AnswerSelection: query-target, target-subtree-class, query-target-filter. Return: rsp-subtree, rsp-subtree-class/-filter, rsp-subtree-include, rsp-prop-include.
  5. (from 2026-11-10) An app reads secret/app fine via the Vault CLI as admin but its token gets 403. What's the likely path error, and how do you find the right path fast?
    AnswerKV v2: the API/policy path is secret/data/app (list uses metadata/). Use -output-curl-string / -output-policy to see the real path.
  6. (from 2026-11-12) A testcase's @aetest.setup raises AssertionError. What happens to its tests, and what does the testcase report?
    AnswerIts tests are Blocked; Failed + Blocked rolls up to Failed.
