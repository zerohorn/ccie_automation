Python Against IOS XE

Date Wed 2026-11-25 Blueprint 3.1 Create/modify/troubleshoot Python scripts against APIs: IOS XE slice Domain 3.0 Network Programmability and Automation (25% per tracker) Tier 2 Read ~18 min Unit 35 of 49 Docs IOS XE 17.5 guide (lab 17.16) · RFC 8040, 7951, 6241 · ncclient 0.7.1 · Requests 2.34.2 · Python 3.13.18

Lab target: router1, Cat8000V at 10.0.0.251. Its CML day-0 config has restconf and ip http secure-server, but not netconf-yang; your notes enable NETCONF by hand. Units 2.4 to 2.6 covered payload shape. Today covers the Python around it: how the script calls the API, and how that call fails.

Mental snapshot

  • A script reaches Cat8000V two ways. RESTCONF is HTTPS, and you call it with requests. NETCONF is SSH on port 830, and you call it with ncclient. Both serve the same YANG models.
  • Every script has the same parts: transport, auth, an address (URI or filter), a payload, and response handling. Most bugs sit in the address and the payload shape, not in the Python.
  • Each RESTCONF verb is a NETCONF edit operation. PATCH merges and never creates the target. PUT creates or replaces. POST only creates, and fails with 409 if the resource exists. DELETE fails if the resource is missing.
  • JSON follows RFC 7951. The top-level member carries its module name. Lists are arrays, even with one entry. 64-bit integers and decimal64 arrive as strings. The empty type arrives as [null].
  • In ncclient, edit_config() targets candidate unless you say otherwise. On IOS XE, enabling candidate makes running read-only to NETCONF. So read the capabilities, then pick the target.
  • Errors come back as data. RESTCONF sends an ietf-restconf:errors body. ncclient raises RPCError with .tag, .path and .message. Print them before you guess.
  • A 2xx status means the device accepted the request, not that the config is right. Read the config back.

Where this fits

L1 · Concept: two doors into one datastore

Every page in units 2.4 to 2.6 started from a YANG path and ended with a payload. Unit 3.1 wraps that payload in a program. The blueprint verbs are create, modify, troubleshoot, so expect three task shapes. In one you write a script from a requirement. In another you extend a working script: add a field, a read-back check, a second device or a flag. In the third you fix a script that fails. All three test the same skill: knowing what each layer of the call should look like, so you can see which layer is wrong.

The 17.5 RESTCONF chapter enables the API with restconf plus ip http secure-server. The 17.5 NETCONF chapter says NETCONF runs over SSH on port 830 by default, and the port can be changed. It needs a privilege 15 user, and only the default AAA login method is supported. The same chapter says IOS XE does not support token-based RESTCONF authentication. So a Python RESTCONF client sends Basic credentials on every request. There is no login call to cache, unlike APIC (11-19) or Catalyst Center.

L2 · Mechanics

A RESTCONF call, layer by layer

Read a RESTCONF URI as a list of YANG node names. The example below is from the Cisco 17.5 chapter, with a fields query added.

https://10.0.0.251/restconf/data/Cisco-IOS-XE-native:native/interface/GigabitEthernet=0%2F0%2F2?fields=name;mtu
Host (TLS; cert check)API root + datastore resourceTop node, module-qualifiedChild, same module: no prefixList instance: list=key, key percent-encodedQuery: GET only

The prefix rule comes from RFC 8040 §3.5.3. A node gets the module: prefix when its parent is the datastore, or when it comes from a different module than its parent. Multiple keys go in YANG key order, separated by commas. Reserved characters in a key value must be percent-encoded, so / becomes %2F. The Cisco chapter shows GigabitEthernet=0%2F0%2F2. The depth and fields query parameters appear in the Cisco examples. RFC 8040 §4.8 allows them only on GET and answers 400 on other methods. depth defaults to unbounded.

Both Cisco and RFC 8040 use application/yang-data+json (or +xml) in Accept and Content-Type. On the Python side, the Requests advanced guide says a Session keeps auth and headers across calls but does not keep method-level parameters. Requests has no default timeout. verify defaults to True, so a lab router's self-signed cert fails until you set verify=False or point at a CA bundle. The Quickstart adds two traps. r.json() raises JSONDecodeError on a 204 response, which has no body. And passing json= sets Content-Type: application/json unless you set the header yourself. An offline test on Requests 2.34.2 confirmed that a session-level Content-Type wins over json=.

A NETCONF session from ncclient

The transport docs list the connect() defaults that matter in a lab: port=830, hostkey_verify=True (checks ~/.ssh/known_hosts), and allow_agent and look_for_keys both True. ncclient tries public-key auth first and password second. The manager docs give the method defaults. get_config(source, filter=None) takes a filter tuple: ("subtree", xml), or ("xpath", expr) with an optional namespace map. edit_config(config, target='candidate', ...) needs config rooted in a <config> element. lock() and unlock() also default to candidate, and locked(target) is a context manager that always unlocks. Manager has a 30 s RPC timeout, and its raise_mode defaults to ALL, so any rpc-error becomes an exception. Read replies return data_xml (a string) and data_ele (an element).

For writes, the operation attribute inside the config does the work. RFC 6241 §7.2 defines five values. merge is the default. replace replaces only the subtree it marks. create fails with data-exists if the data is already there. delete fails with data-missing if the data is absent. remove deletes the data and is silently ignored if it is absent. A teardown script that must be rerunnable uses remove. A guard against overwriting uses create.

L3 · Exam detail

1. The percent-encoding trap

urllib.parse.quote has safe='/' by default, because it is built for whole URL paths. quote("0/0/2") returns the string unchanged. The device then reads GigabitEthernet=0 followed by two extra path segments. Encode each key with quote(value, safe=""). Cat8000V interface names (GigabitEthernet1) have no slash, so a script can pass in the lab and fail on a switch with 1/0/1 ports.

2. Decoding RFC 7951 JSON

RFC 8040 §4.3 adds a trap for XML: a GET that matches more than one list instance must return 400 when the response is XML. Ask for JSON, or GET the parent container.

3. Errors are structured, so print the structure

RFC 8040 §7 sends NETCONF error fields inside {"ietf-restconf:errors": {"error": [...]}} and maps each error-tag to a status code. ncclient's RPCError exposes the same fields as attributes. Your error printer should look the same on both paths.

4. Datastore choice and leftover locks

The 17.5 NETCONF chapter says that with the candidate datastore enabled, running is not writable through NETCONF sessions, and :writable-running is not advertised. ncclient's default target is candidate. That gives two opposite failures. With the feature off, a bare edit_config(cfg) goes to candidate, and the device rejects it. With the feature on, target="running" is rejected. In both cases ncclient 0.7.1 sends the RPC without checking first, and the device's rpc-error comes back as RPCError. commit() is different: it depends on :candidate, and ncclient raises MissingCapabilityError before sending anything. The capabilities docs allow shorthand tests such as ":candidate" in m.server_capabilities, so choose the target at runtime.

If a script crashes while holding a lock, the lock stays until that session ends. Other clients get lock-denied (409 on RESTCONF in the RFC 8040 example). Per the 17.5 chapter, clear netconf-yang session clears both the NETCONF lock and the configuration lock. The 17.5 chapter also says RESTCONF has no confirmed commit. When a task needs "apply, and roll back if the box stops answering", that points to NETCONF with commit(confirmed=True).

5. "Modify" tasks: the usual changes

  • Make it rerunnable. Swap POST for PUT on the list-instance URI. On NETCONF, swap create for merge or replace.
  • Add verification. After every write, read back with fields= or a subtree filter and compare to intent. Return a non-zero exit code on mismatch so CI (1.3/1.4) can gate on it.
  • Scale out. Loop over an inventory. Keep one Session or one Manager per device, and set a timeout on every call.
  • Harden. Catch requests.exceptions.ConnectionError/Timeout and ncclient's TimeoutExpiredError, AuthenticationError and SSHUnknownHostError separately. A bare except: hides which layer failed.

Anatomy

Building blocks pinned to Python 3.13, Requests 2.34.2 and ncclient 0.7.1. The helpers were run offline against sample bodies (the RFC 8040 §3.6 error example and a 204). They have not been run against a device.

# RESTCONF core: one Session, encoded keys, one error printer
import sys
from urllib.parse import quote
import requests

BASE = "https://10.0.0.251/restconf/data"
s = requests.Session()
s.auth = ("admin", "automation")             # Basic on every call; user needs priv 15
s.verify = False                             # lab self-signed cert; True by default
s.headers.update({"Accept": "application/yang-data+json",
                  "Content-Type": "application/yang-data+json"})

def key(v):                                  # "0/0/2" -> "0%2F0%2F2"
    return quote(str(v), safe="")

def explain(r):
    if r.ok:
        return r.json() if r.content else None          # 201/204: no body
    try:
        errs = r.json()["ietf-restconf:errors"]["error"]
    except (requests.exceptions.JSONDecodeError, KeyError):
        r.raise_for_status()                             # non-RESTCONF error page
    for e in errs:
        print(r.status_code, e.get("error-tag"), e.get("error-path"), e.get("error-message"))
    sys.exit(1)

r = s.get(f"{BASE}/Cisco-IOS-XE-native:native/interface/GigabitEthernet={key('0/0/2')}",
          params={"fields": "name;mtu"}, timeout=(5, 30))  # (connect, read); per call, not persisted
print(explain(r))
# NETCONF write: target chosen from capabilities, lock released on any exit
from ncclient import manager
from ncclient.operations import RPCError

with manager.connect(host="10.0.0.251", port=830, username="admin",
                     password="automation", hostkey_verify=False,
                     look_for_keys=False, allow_agent=False) as m:
    cand = ":candidate" in m.server_capabilities      # shorthand capability test
    try:
        if cand:
            with m.locked("candidate"):
                try:
                    m.edit_config(config=CFG, target="candidate")  # CFG rooted in <config>
                    m.commit()                    # needs :candidate, else MissingCapabilityError
                except RPCError:
                    m.discard_changes()           # still holding the lock here
                    raise
        else:
            m.edit_config(config=CFG, target="running")    # never rely on the default
    except RPCError as e:                         # raise_mode ALL: any rpc-error lands here
        print(e.tag, e.path, e.message)
        raise
# NETCONF read: subtree filter, parse the string with stdlib ElementTree
import xml.etree.ElementTree as ET
flt = ('<native xmlns="http://cisco.com/ns/yang/Cisco-IOS-XE-native">'   # ⚠ ns URI
       '<hostname/></native>')
reply = m.get_config(source="running", filter=("subtree", flt))
root = ET.fromstring(reply.data_xml)
print(root.findtext(".//{*}hostname"))      # {*} = any namespace (3.8+)

The {*} wildcard works in find/findall/findtext paths, per ElementTree's namespace section. An offline test showed that iter("{*}name") matched nothing, so use findall(".//{*}name") instead.

Speed notes (offline on the workstation)

  • Library help without docs: python -c "from ncclient import manager; help(manager.connect_ssh)" and python -c "import ncclient.operations as o; help(o.EditConfig.request)" show the signatures above. Manager builds its methods dynamically, so help(manager.Manager.edit_config) fails. Confirmed offline on 0.7.1.
  • What's installed: the Equipment and Software List says the Python libraries come from a pyproject.toml/uv.lock. Check that file for ncclient and requests before you design around them. ⚠ file not in repo
  • Shape discovery: configure the object once by CLI, GET it with ?depth=2 or ?fields=, and reuse that JSON as the PUT body. This is quicker and safer than hand-building from the YANG tree.
  • Root discovery: curl -k -u admin:automation -H "Accept: application/yang-data+json" https://10.0.0.251/restconf gives a known-good control test. If curl works and Python fails, the bug is in your headers, auth or encoding.
  • Model discovery over NETCONF: iterate m.server_capabilities for module URIs, then m.get_schema("Cisco-IOS-XE-native") to pull the YANG text (the 17.5 chapter lists get-schema). Run it through YANG Suite 3.0 (on the CWS list) or pyang -f tree. ⚠ pyang on CWS
  • Device side: show netconf-yang sessions detail, clear netconf-yang session, and show platform software yang-management process (all in the 17.5 chapters).

Micro-drill (~10 min)

Target: router1 (Cat8000V, 10.0.0.251). Do netconf-yang first if it is not on.

Requirement: write loopback_probe.py. It must:

  1. Over RESTCONF, make Loopback101 exist with description mgmt-probe and 10.255.101.1/32. Running the script twice must succeed both times.
  2. Print each HTTP status. On failure, print error-tag, error-path and error-message, then exit 1.
  3. Over NETCONF, read the Loopback101 config back with a subtree filter, print PASS or FAIL, and exit 2 on FAIL.

Reference names (check on the device): URI /restconf/data/Cisco-IOS-XE-native:native/interface/Loopback=101; body under ip/address/primary with address and mask (the path follows the Cisco fields example). Native namespace http://cisco.com/ns/yang/Cisco-IOS-XE-native. ⚠ leaf names, key type, ns URI

Verify: show running-config interface Loopback101. The first run's PUT should return 201 and the second 204 (RFC 8040 §4.5). During step 3, show netconf-yang sessions shows your session. To clean up, DELETE the same URI and expect 204.

HintPUT to the list-instance URI is the rerunnable verb. The body is an array of one object under a module-qualified key, and its name must equal the URI key. Get the exact shape by configuring Loopback100 by CLI and running a GET on .../interface/Loopback=100.
Solution 
#!/usr/bin/env python3
import sys
import xml.etree.ElementTree as ET
import requests
from ncclient import manager
from ncclient.operations import RPCError

HOST, USER, PWD = "10.0.0.251", "admin", "automation"
NATIVE = "Cisco-IOS-XE-native"
NS = "http://cisco.com/ns/yang/Cisco-IOS-XE-native"
URI = f"https://{HOST}/restconf/data/{NATIVE}:native/interface/Loopback=101"
BODY = {f"{NATIVE}:Loopback": [{
    "name": 101, "description": "mgmt-probe",
    "ip": {"address": {"primary": {"address": "10.255.101.1",
                                   "mask": "255.255.255.255"}}}}]}

def restconf_put():
    s = requests.Session()
    s.auth, s.verify = (USER, PWD), False
    s.headers.update({"Accept": "application/yang-data+json",
                      "Content-Type": "application/yang-data+json"})
    r = s.put(URI, json=BODY, timeout=(5, 30))
    print("PUT", r.status_code)
    if not r.ok:
        try:
            for e in r.json()["ietf-restconf:errors"]["error"]:
                print(e.get("error-tag"), e.get("error-path"), e.get("error-message"))
        except (requests.exceptions.JSONDecodeError, KeyError):
            print(r.text[:300])
        sys.exit(1)

def netconf_check():
    flt = (f'<native xmlns="{NS}"><interface><Loopback>'
           f'<name>101</name></Loopback></interface></native>')
    with manager.connect(host=HOST, port=830, username=USER, password=PWD,
                         hostkey_verify=False, look_for_keys=False,
                         allow_agent=False) as m:
        try:
            reply = m.get_config(source="running", filter=("subtree", flt))
        except RPCError as e:
            print("rpc-error", e.tag, e.path, e.message)
            sys.exit(1)
    ip = ET.fromstring(reply.data_xml).findtext(".//{*}primary/{*}address")
    print("PASS" if ip == "10.255.101.1" else f"FAIL got {ip!r}")
    return ip == "10.255.101.1"

if __name__ == "__main__":
    restconf_put()
    sys.exit(0 if netconf_check() else 2)

Compiled with Python 3.13 and run offline, with the XML parse tested on a sample reply. Not run against router1. The native-model leaf names are ⚠.

Recall check

Today

  1. Your script PATCHes a list entry that does not exist, and POSTs one that does. What does RFC 8040 say happens in each case, and which verb makes the script rerunnable?
    AnswerPATCH: the server must not create the target, so the call fails (404 is allowed). POST to an existing resource: 409 Conflict. PUT on the list-instance URI creates (201) or replaces (204), so reruns succeed.
  2. s.get(base + "/interface/GigabitEthernet=" + quote("0/0/2")) still returns 404. Why, and what is the fix?
    Answerquote() defaults to safe='/', so the slashes stay and the device sees extra path segments. Use quote("0/0/2", safe=""), which gives 0%2F0%2F2, the form in the Cisco 17.5 example.
  3. On a Cat8000V with only netconf-yang configured, m.edit_config(config=cfg) fails. Why? What changes if you enable the candidate feature and send target="running"?
    Answerncclient defaults the target to candidate, which this device lacks. ncclient 0.7.1 sends the RPC anyway, and the device's rpc-error is raised as RPCError. With candidate enabled, running is not writable through NETCONF and :writable-running is not advertised, so the running edit fails instead. Pick the target from ":candidate" in m.server_capabilities and commit after candidate edits.
  4. A JSON GET returns "in-octets": "123456" as a string. Why? Name two other RFC 7951 encodings that break a naive dict walk.
    Answer64-bit integer types (and decimal64) are encoded as JSON strings, so int() them before doing math. Others: lists are always arrays, even with one entry; the empty type is [null]; an identityref carries a module prefix (iana-if-type:ethernetCsmacd); the top-level member is module-qualified. ⚠ Check that leaf's base type in its YANG.

From history

  1. (from 2026-11-19) Name the three APIC session endpoints, what each takes, and the aaaRefresh detail that breaks naive token caching.
    AnsweraaaLogin: POST an aaaUser with name and pwd. aaaRefresh: GET with no body. aaaLogout: POST an aaaUser with name. The token changes on each refresh, so store the new one. The default timeout is 600 s; read refreshTimeoutSeconds. Contrast with today: IOS XE RESTCONF has no token at all and sends Basic auth on every call. (Restated from the 2026-11-19 page.)
  2. (from 2026-11-16) A request carries a well-formed, unexpired JWT whose scope lacks the needed value. Which status code and RFC 6750 error code apply?
    Answer403 Forbidden with error="insufficient_scope" (RFC 6750 §3.1). 401 is for a missing or invalid token. (Restated from the 2026-11-16 page.)
