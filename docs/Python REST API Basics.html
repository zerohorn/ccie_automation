2.1 Build, manage and operate a Python REST API with a web framework

Domain 2 (weight ⚠ unverified)Blueprint text: endpoints, HTTP request/response, OpenAPI spec

Mental snapshot

  • A REST API is a mapping from (HTTP method, path) to a Python function. The framework does routing, parsing, validation, serialization and docs; you write the functions.
  • FastAPI: types in the function signature drive everything. Path params, query params and body are told apart by declaration, and the OpenAPI document is generated from the same code.
  • Flask: lighter. Decorator routing and a dict/list return becomes JSON, but validation and an OpenAPI document are your problem.
  • Status codes are part of the contract: 201 on create, 204 with no body, 404 for a missing resource, a 4xx for bad input. Getting them right is how a client (and a grader) can tell your API works.
  • "Operate" means you can start it, call it with curl, read its error responses, fetch /openapi.json and run a test against it.
  • The blueprint does not name a framework. Pick FastAPI as primary since it ships the OpenAPI output the blueprint mentions; know Flask's equivalents.

Where this fits

Fundamentals to exam depth

L1: Concept

You already know REST from the consumer side (2.3). Here you are the server. A request arrives as a method, a path, headers and an optional body. Your code returns a status, headers and a body. A web framework removes the plumbing between the socket and your function.

FastAPI's vocabulary: the path is the part of the URL starting at the first /, an operation is the HTTP method, the path operation decorator (@app.get("/")) binds the pair to the path operation function beneath it [First Steps]✅. Flask calls the same thing a route and a view function [Flask Quickstart]✅.

L2: Mechanics

Walk one request through a FastAPI app:

Parameter placement is by declaration. In FastAPI, a name that appears in the path is a path parameter, a singular type (int, str) is a query parameter, and a Pydantic model is the request body; a default makes it optional [Request Body]✅. A model attribute with None default is optional, so {"name":"Foo","price":45.2} is valid for the page's Item.

Output is shaped separately. response_model (or a return annotation) filters what leaves; if both are given, response_model wins. The page's password example uses an input model with password and an output model without it [Response Model]✅. response_model_exclude_unset=True drops fields that were never explicitly set, but keeps explicitly set values even if they equal the default.

The status is set on the decorator: status_code=201, or status.HTTP_201_CREATED from fastapi for autocomplete. The tutorial calls 201 "commonly used after creating a new record" and 204 the case where "the response must not have a body" [Response Status Code]✅. Status semantics themselves live in RFC 9110✅ (title confirmed; I could only read part of it, so section numbers are not cited).

Errors: you raise HTTPException(status_code=404, detail="Item not found"), you do not return it; the client sees {"detail": "Item not found"}. Bad input never reaches your function: FastAPI raises RequestValidationError and answers with a JSON detail list whose entries carry loc, msg and type. You can override that handler and return a different status [Handling Errors]✅. The page's own sample body shows an old type_error.integer type string, so do not memorise exact type values.

The OpenAPI document comes free: the first-steps page lists Swagger UI at /docs, ReDoc at /redoc and the schema at /openapi.json. The format is defined by the spec: an OpenAPI Object has required openapi and info fields, plus paths, components, servers, security and others, and an operationId must be unique across all operations [OpenAPI Specification v3.1.1]✅. A document can be JSON or YAML.

Anatomy

Annotated minimal pieces, all taken from the fetched pages. This is not a solution to the drill.

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

class Item(BaseModel):            # body model: attrs with defaults are optional
    name: str
    description: str | None = None
    price: float

app = FastAPI()

@app.post("/items/", status_code=201)       # status on the decorator
async def create_item(item: Item):          # model type => request body
    return item

@app.get("/items/{item_id}")                # path param by name match
async def read_item(item_id: str):
    if item_id not in items:                # items: your own dict
        raise HTTPException(status_code=404, detail="Item not found")
    return {"item": items[item_id]}
# Flask equivalent of the JSON-returning pieces
from flask import Flask, abort
app = Flask(__name__)

@app.route("/users")
def users_api():
    return [u.to_json() for u in get_all_users()]   # list => JSON

@app.route("/login")
def login():
    abort(401)                                      # ends request early
# test (FastAPI): plain def, no await
from fastapi.testclient import TestClient
client = TestClient(app)
def test_read_main():
    r = client.get("/")
    assert r.status_code == 200

Speed notes (offline on the workstation)

  • Start the server, then open /docs and /openapi.json; the generated schema is your offline reference for what the app actually exposes.
  • curl -i shows status and headers; curl -s localhost:8000/openapi.json | python -m json.tool prints the schema (⚠ port and tools to confirm).
  • python -c "import fastapi,pydantic;print(fastapi.__version__,pydantic.VERSION)" to see versions. ⚠ unverified that FastAPI is installed; check with uv pip list.
  • FastAPI docs show fastapi dev but I did not verify which extras provide the command (⚠). If missing, uvicorn main:app is the fallback, also ⚠.
  • Python's built-in help() on fastapi.HTTPException works offline.

Micro-drill (~10 min)

Target: local only, no device. A tiny device inventory API (the kind of source of truth your Ansible tasks could read).

Requirement

  • POST /devices accepts name (str, required), mgmt_ip (str, required), role (str, optional). Returns 201 and the stored device without any extra internal field you add.
  • GET /devices/{name} returns the device or 404 with a detail message.
  • DELETE /devices/{name} returns 204 with no body.
  • Storage is an in-memory dict.

Verify

  • POST valid body: status 201.
  • POST without mgmt_ip: error response, and your function did not run.
  • GET unknown name: 404 with your detail text.
  • DELETE then GET: 204, then 404.
  • /openapi.json lists all three paths.
  • Write one TestClient test for the 404 case.
Hint

Input model and output model can differ. Put the internal field only on the input side or add it in your storage layer, then set response_model to the model without it. Remember raise, and that a 204 must not return a body.

Solution outline
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

class DeviceIn(BaseModel):
    name: str
    mgmt_ip: str
    role: str | None = None

app = FastAPI()
db: dict[str, DeviceIn] = {}

@app.post("/devices", status_code=201, response_model=DeviceIn)
async def add(d: DeviceIn):
    db[d.name] = d
    return d

@app.get("/devices/{name}", response_model=DeviceIn)
async def get(name: str):
    if name not in db:
        raise HTTPException(status_code=404, detail="Device not found")
    return db[name]

@app.delete("/devices/{name}", status_code=204)
async def delete(name: str):
    db.pop(name, None)

⚠ unverified — test in lab: 204 handler returning None and the DELETE of an unknown name behavior.

Recall check

Today

  1. A POST handler is declared with item: Item and q: str. Where does each value come from in the request?
  2. You want 201 on create and a response that omits password. Which two arguments or annotations do you use, and which wins if you give both a model and an annotation?
  3. Your lookup returns 200 with nothing for a missing id. What is the one-word fix and what shows in the body?
  4. Name the three built-in URLs FastAPI serves after startup and what each is.
Answers (today)
  1. item from the JSON body (model type); q from the query string (singular type, not in path).
  2. status_code=201 on the decorator and response_model (or a return annotation) pointing at a model without the password; response_model takes priority.
  3. raise an HTTPException(status_code=404, detail=...); body is {"detail": "..."}.
  4. /docs Swagger UI, /redoc ReDoc, /openapi.json the schema.
