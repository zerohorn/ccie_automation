1HTTPAPI connection + facts (2.7.d)

Requirement

Build an apic_devices inventory group using the httpapi connection plugin with cisco.aci.aci as the network OS. Then run a query-only play with cisco.aci.aci_tenant against the built-in common tenant — this proves connectivity/auth before you provision anything, without risking any object that matters.

Reference

  • Connection vars: ansible_connection: httpapi, ansible_network_os: cisco.aci.aci, ansible_httpapi_use_ssl: true, ansible_httpapi_validate_certs: false
  • cisco.aci.aci_tenant: tenant (name), description, state (present/absent/query) — state: query with no other filters just reads back the object

Docs

  • cisco.aci.aci_tenant
  • cisco.aci module index

Verification

ansible-playbook -i inventory.yml facts.yml

Registered output should show common's DN (uni/tn-common) under current, not a connection/auth error.

Hint

Unlike network_cli, httpapi needs no per-platform cliconf — cisco.aci.aci is a complete, self-contained network OS value for this connection type, which is exactly why HTTPAPI is the one connection-plugin leg of 2.7.d this equipment list can actually exercise.

Put connection vars once under group_vars/apic_devices.yml rather than repeating per host.

Solution
# inventory.yml
all:
  children:
    apic_devices:
      hosts:
        apic1:
          ansible_host: 10.0.0.31
      vars:
        ansible_connection: httpapi
        ansible_network_os: cisco.aci.aci
        ansible_httpapi_use_ssl: true
        ansible_httpapi_validate_certs: false
        ansible_user: "{{ vault_apic_user }}"
        ansible_password: "{{ vault_apic_password }}"

# facts.yml
- name: Query the built-in common tenant
  hosts: apic_devices
  gather_facts: false
  tasks:
    - name: Read common tenant
      cisco.aci.aci_tenant:
        tenant: common
        state: query
      register: common_out

    - name: Show tenant DN
      debug:
        var: common_out.current[0].fvTenant.attributes.dn

2Variables & templating (2.7.c)

Requirement

Externalize APIC connection vars (mark credentials sensitive via vault), plus a variable representing a set of EPGs you'll provision in Task 3 — a map keyed by tier name, each value at least a display name and a description.

Reference

  • cisco.aci.aci_epg (used in Task 3) takes epg (name) and description as plain strings — no special typing constraint on your variable's shape

Docs

  • Variables · Templating (Jinja2) · ansible-vault

Verification

ansible-inventory -i inventory.yml --host apic1

Should resolve vault_apic_user/vault_apic_password without prompting for a missing variable, and print your EPG map.

Hint

A map like epgs: { web: { name: WEB, description: "web tier" }, app: {...}, db: {...} } sets up Task 3's loop and its Jinja2 templating (e.g. {{ item.value.name | upper }}) in one shot.

Solution
# group_vars/apic_devices/vars.yml
lab_tenant_name: CCIE_LAB
app_profile_name: STUDY_AP

epgs:
  web: { name: web, description: "Web tier EPG" }
  app: { name: app, description: "App tier EPG" }
  db:  { name: db,  description: "DB tier EPG" }

# group_vars/apic_devices/vault.yml (ansible-vault encrypted)
vault_apic_user: admin
vault_apic_password: "..."

3Provisioning + loop control (2.7.a)

Requirement

Provision one cisco.aci.aci_tenant, one cisco.aci.aci_ap (application profile) underneath it, and one cisco.aci.aci_epg per entry in your Task 2 map — driven by Ansible's own loop keyword, not a pre-expanded list of tasks.

Reference

  • cisco.aci.aci_tenant: tenant (name), description, state
  • cisco.aci.aci_ap: tenant, ap (name), description, state
  • cisco.aci.aci_epg: tenant, ap, epg (name), description, state

Docs

  • aci_tenant · aci_ap · aci_epg
  • Loops

Verification

ansible-playbook -i inventory.yml provision.yml

Then on the APIC GUI: Tenants → CCIE_LAB → Application Profiles → STUDY_AP → Application EPGs should list all three EPGs. Re-run the playbook — it should report no changes (idempotent).

Hint

loop: "{{ epgs | dict2items }}", addressing the current item as item.value.name/item.value.description; add loop_control: { label: "{{ item.key }}" } so playbook output shows tier names instead of full dicts.

Build the EPG's live description with a Jinja2 filter, e.g. {{ item.value.description | upper }}, to hit 2.7.c's templating angle in the same task.

Solution
- name: Provision ACI tenant, AP, and EPGs
  hosts: apic_devices
  gather_facts: false
  tasks:
    - name: Create tenant
      cisco.aci.aci_tenant:
        tenant: "{{ lab_tenant_name }}"
        description: "CCIE Automation study tenant - safe to destroy/recreate"
        state: present

    - name: Create application profile
      cisco.aci.aci_ap:
        tenant: "{{ lab_tenant_name }}"
        ap: "{{ app_profile_name }}"
        state: present

    - name: Create one EPG per loop iteration
      cisco.aci.aci_epg:
        tenant: "{{ lab_tenant_name }}"
        ap: "{{ app_profile_name }}"
        epg: "{{ item.value.name }}"
        description: "{{ item.value.description | upper }}"
        state: present
      loop: "{{ epgs | dict2items }}"
      loop_control:
        label: "{{ item.key }}"

4Conditionals (2.7.b)

Requirement

Create a cisco.aci.aci_contract under your tenant, then bind two EPGs to it via cisco.aci.aci_epg_to_contract — but only when a variable flags the environment as ready for east-west traffic. Run the play with the flag both unset and set, and confirm the binding tasks are skipped/applied accordingly.

Reference

  • cisco.aci.aci_contract: tenant, contract (name), scope, state
  • cisco.aci.aci_epg_to_contract: tenant, ap, epg, contract, contract_type (provider/consumer), state
  • when evaluates a Jinja2 expression without the surrounding {{ }}

Docs

  • aci_contract · aci_epg_to_contract
  • Conditionals

Verification

ansible-playbook -i inventory.yml contract.yml -e enable_contracts=false -vv
ansible-playbook -i inventory.yml contract.yml -e enable_contracts=true -vv

First run should show skipping on both binding tasks; second should apply them and show up under web EPG → Contracts and app EPG → Contracts on the APIC GUI, one as provider and one as consumer.

Hint

when: enable_contracts | default(false) | bool guards both binding tasks — the contract object itself can still always be created, only the EPG bindings are conditional.

Solution
- name: Conditionally bind a web-to-app contract
  hosts: apic_devices
  gather_facts: false
  tasks:
    - name: Create contract
      cisco.aci.aci_contract:
        tenant: "{{ lab_tenant_name }}"
        contract: WEB_TO_APP
        scope: tenant
        state: present

    - name: Bind web EPG as provider
      cisco.aci.aci_epg_to_contract:
        tenant: "{{ lab_tenant_name }}"
        ap: "{{ app_profile_name }}"
        epg: "{{ epgs.web.name }}"
        contract: WEB_TO_APP
        contract_type: provider
        state: present
      when: enable_contracts | default(false) | bool

    - name: Bind app EPG as consumer
      cisco.aci.aci_epg_to_contract:
        tenant: "{{ lab_tenant_name }}"
        ap: "{{ app_profile_name }}"
        epg: "{{ epgs.app.name }}"
        contract: WEB_TO_APP
        contract_type: consumer
        state: present
      when: enable_contracts | default(false) | bool

5Stretch — package as a role

Requirement

Convert Tasks 1–4 into a proper Ansible role — roles/aci_baseline/{tasks,defaults,vars}/main.yml — parameterized via role defaults (tenant name, AP name, EPG map, contract-enable flag), invoked from a single top-level playbook. This is the literal wording of 2.7 ("create/use an Ansible role to manage infrastructure"), so it's worth doing for real rather than skipping to the next topic.

ansible-galaxy init roles/aci_baseline
