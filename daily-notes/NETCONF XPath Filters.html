Mental snapshot

  • A filter limits what <get> or <get-config> returns. Two flavors exist: subtree (default) and XPath (type="xpath" with a select attribute).
  • XPath is optional. The server must advertise the :xpath capability in its hello, and many platforms do not. NX-OS 9.3 says it does not support it; check IOS XE on the Cat8000V before you rely on it.
  • XPath 1.0 matches names in a namespace. An unprefixed name in XPath 1.0 means "no namespace", so a path copied from a YANG tree matches nothing until you bind a prefix.
  • Selecting by key uses a predicate: [name='1']. That is the whole point of XPath over subtree: pick a row, not a branch.
  • A filter that matches nothing is not an error. You get an empty <data/>. That makes silent namespace mistakes easy to miss.
  • The same XPath idea reappears in telemetry as filter xpath ... (blueprint 3.5), with a different prefix convention and tighter restrictions.
  • Exam task shape (consistent with the blueprint verb "Create"): given a YANG model and a device, build a working filter, send it, and show the response contains only what was asked.

Where this fits

Fundamentals to exam depth

L1. Concept

NETCONF returns the whole datastore unless you narrow it. Narrowing happens in the <filter> element inside <get> or <get-config>. RFC 6241 defines the default filter as subtree, and states that a peer supporting the :xpath capability may use type="xpath", with the expression in the select attribute.

Think of subtree as a template you fill in: you draw the shape of the data you want and the server returns whatever fits the shape. XPath is a query: you write an expression and the server returns the nodes it selects. If you have done XML work, XPath 1.0 is the same language you would use in XSLT. If you have not, you need four ideas: location steps (/a/b), predicates ([name='1']), wildcards (*), and namespaces.

L2. Mechanics

Subtree filtering has five node roles in RFC 6241 section 6.2: namespace selection, attribute match, containment node, selection node (an empty leaf, meaning "give me this leaf"), and content match node (a leaf with a value, meaning "only rows where this leaf equals this value"). Several content match nodes in the same set combine with AND. Unqualified elements act as wildcards across namespaces.

XPath works differently. The expression is evaluated against the datastore and returns a node-set. Each step walks down the tree and each predicate keeps or drops candidates. For lists, the key predicate replaces the content match node. The tree you walk is the YANG data tree: for example a list interface with key name becomes /interfaces/interface[name='GigabitEthernet1'].

The namespace is where people lose time. In XPath 1.0 a bare name tests "no namespace". YANG data is always in a module namespace. So a NETCONF client must declare a prefix in the XML (xmlns:ios="...") and use ios: in every step. RFC 6241 section 8.9.1 governs how the server resolves prefixes for <get>, but that section was beyond what the fetch tool could read this run, so treat the exact resolution rule as ⚠ unverified and test it. What is verified: RFC 8641 (subscriptions) binds prefixes from the YANG module prefixes and namespaces the server implements, with no variables, and uses the datastore root as the context node. Cisco's telemetry CLI follows that style: /memory-ios-xe-oper:memory-statistics/memory-statistic, with the module name as the prefix and nothing declared.

Restrictions the IOS XE 17.5 telemetry chapter spells out for subscription XPath: key names and values must be exact, with no ranges or wildcards; the union operator | works only with NETCONF transport, not gRPC; and for on-change with yang-notif-native, the path must name a whole YANG notification. Those are subscription rules. Whether a plain <get> on the Cat8000V accepts wildcards, unions or comparison predicates is ⚠ unverified: test it.

A practical way to choose: use subtree when the target supports it and you want a branch; use XPath when you need a single list row by key, a value comparison, or a path you already have from a YANG tool. In exam terms, pick the one the device actually accepts, and prove the result is narrowed by comparing the response size or content against an unfiltered get.

Anatomy

Snippets are pinned to the versions named. They show the shape, not the drill answer.

NX-OS 9.3(x): subtree, as the guide shows it ✅

<rpc message-id="111" xmlns="urn:ietf:params:xml:ns:netconf:base:1.0">
  <get>
    <filter>
      <System xmlns="http://cisco.com/ns/yang/cisco-nx-os-device">
        <intf-items><phys-items>
          <PhysIf-list><id>eth1/54/1</id></PhysIf-list>
        </phys-items></intf-items>
      </System>
    </filter>
  </get>
</rpc>

<id> is a content match node: it picks one list row. The XPath equivalent would be a predicate, but the same guide says XPath is unsupported on this platform, so there is no XPath answer to give on N9Kv.

IOS XE: XPath filter on the wire ⚠ unverified — test in lab

<rpc message-id="1" xmlns="urn:ietf:params:xml:ns:netconf:base:1.0">
  <get-config>
    <source><running/></source>
    <filter type="xpath"
            xmlns:ios="http://cisco.com/ns/yang/Cisco-IOS-XE-native"
            select="/ios:native/ios:interface/ios:GigabitEthernet[ios:name='1']"/>
  </get-config>
</rpc>

Three things to check in the reply: it contains only interface 1, the leaves arrive in the native namespace, and nothing else from the running config came back. Whether this exact prefix declaration is how the Cat8000V resolves names is the open question above.

Telemetry subscription CLI, IOS XE 17.5 ✅

Device(config-mdt-subs)# filter xpath /memory-ios-xe-oper:memory-statistics/memory-statistic

Module name as prefix, nothing declared. An extra slash after the colon produces an invalid subscription, per Cisco's YANG Suite telemetry article.

Ansible netconf_get with XPath ✅ (netcommon docs 8.6.2, lab 8.4.0)

- ansible.netcommon.netconf_get:
    filter: /netconf-state/schemas/schema
    display: xml

That example reads the schema list from the NETCONF monitoring module. It works only if the server has the xpath capability. How to pass namespace bindings through this module is ⚠ unverified.

Speed notes

  • See the capability list first. A raw hello over SSH subsystem works from the workstation: ssh -s -p 830 user@host netconf ⚠ unverified on this lab; look for the xpath capability URI in the output.
  • Get exact namespaces from the device, not memory: an unfiltered get on the node and read the xmlns attribute.
  • Session state: show netconf-yang sessions and show netconf-yang datastores (both in the IOS XE 17.5 chapter).
  • Pull the schema list from the device with the XPath shown in the netconf_get docs, then read a module: this is the offline-safe way to learn paths.
  • ansible-doc ansible.netcommon.netconf_get shows the filter parameter and examples without a browser.
  • pyang -f tree module.yang gives the key names for predicates; ⚠ confirm pyang and the YANG files exist on the workstation.

Micro-drill (about 10 min)

Target: Cat8000V only (IOS XE 17.16 in lab; guides are 17.5). IOSvL2 has no RESTCONF and IOSv is CLI only.

Requirement: Return the running configuration for GigabitEthernet1 and nothing else, once with a subtree filter and once with an XPath filter. Then subscribe to memory statistics with an XPath filter.

Reference names (⚠ unverified until you read them off the device): module Cisco-IOS-XE-native, path native/interface/GigabitEthernet, key name. Telemetry path: /memory-ios-xe-oper:memory-statistics/memory-statistic.

Verification:

  • The reply for each filter contains one GigabitEthernet element and no other interfaces.
  • Both replies carry the same leaves.
  • A deliberately wrong prefix returns empty <data/> and no error.
  • show telemetry ietf subscription all shows the subscription valid (⚠ confirm command output on 17.16).
Hint

Do an unfiltered get-config of the interface node first and copy the namespace URI from the reply. If the XPath form returns nothing, check capabilities before you debug quoting.

Solution

Subtree: a filter containing native (native namespace) → interface → GigabitEthernet → name with value 1. XPath: the anatomy snippet above with the prefix bound to the namespace you read from the device. If the device does not advertise xpath, record that fact and finish with the subtree form; it is a legitimate outcome. Subscription (IOS XE 17.5 syntax from the guide): create the subscription in config-mdt mode, set filter xpath /memory-ios-xe-oper:memory-statistics/memory-statistic, and add the stream, update policy, encoding, source VRF and receiver lines as in the 2026-10-06 page. ⚠ unverified on 17.16.

Recall check

Today

1. An XPath filter returns success and empty data. List the two most likely causes and how you tell them apart.

Namespace prefix missing or wrong URI, versus an expression that matches nothing (wrong key value or path). Run an unfiltered get on the node: if the element exists and you copy its xmlns and path exactly, a still-empty result points to the predicate, not the namespace.

2. Name two places in the guides where XPath is stated unsupported or restricted, and the restriction.

NX-OS 9.3 NETCONF agent: XPath filtering unsupported, subtree only. IOS XE 17.5 telemetry: exact key names and values only, no wildcards or ranges; union only over NETCONF transport; subtree filters make a subscription invalid.

3. Which filter node role in a subtree filter corresponds to an XPath key predicate?

The content match node (a leaf with a value). A selection node (empty leaf) corresponds to naming the leaf as the last step.

4. Where does the xpath capability show up and what do you do if it is absent?

In the server hello capabilities. If absent, use a subtree filter; RFC 6241 allows XPath only when the peer supports the capability.

From history

5. (2026-09-28) Why does IOSvL2 accepting restconf into its configuration not mean RESTCONF works there?

The command is accepted but the YANG/RESTCONF agent is absent; the tracker notes 404 on every request. Test the endpoint, do not trust the CLI.

6. (2026-09-30) The first task in an imported file sets x; the import carries when: x is not defined. What happens to the remaining tasks, and what changes with include_tasks?

With import, the condition is applied to each task, so after the first sets x the rest are skipped. With include_tasks the condition is evaluated once for the include, so all tasks run.
