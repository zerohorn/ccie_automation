2.3 Consume and use a new API given documentation (REST, GraphQL)

Date 2026-10-05 (Mon)Blueprint 2.3.a REST, 2.3.b GraphQLDomain 2.0 Infrastructure as Code, 30%Tier 2Read ~18 minUnit 5 of 49

Mental snapshot

  • The verb is consume: you get docs you have never seen and must produce a working call. The skill is reading docs fast, not memorizing endpoints.
  • Every doc answers the same five questions: base URL and path, auth, request shape, response shape, how big results are paged. Find those five first, in that order.
  • REST puts meaning in the URL and the method. GraphQL puts meaning in the request body, behind one endpoint, and almost always uses POST.
  • Cisco REST APIs differ in the details that bite: token header (X-Auth-Token on Catalyst Center), cookie session (APIC-cookie on APIC), and pagination style (Link header on Meraki, page/page-size on APIC).
  • GraphQL returns HTTP 200 with an errors array more often than you expect. Check the body, not just the status.
  • If the schema is unknown, GraphQL can describe itself through introspection. REST has no equivalent; you rely on the spec or docs you were handed.

Where this fits

Fundamentals to exam depth

L1: Concept

A REST API exposes resources at URLs and uses HTTP methods as verbs. GET reads, POST creates or acts, PUT replaces, PATCH modifies part, DELETE removes. The status code tells you what happened and the body carries the representation, usually JSON. RFC 9110 defines these semantics: safe and idempotent methods are in its section 9.2, and status code classes are in section 15 (RFC 9110). 401 means authenticate (missing or bad credentials); 403 means you are known but refused.

GraphQL exposes a typed schema behind a single endpoint. The client sends a document that names the fields it wants, and the server returns exactly that shape. There are three operation types: query (read), mutation (write), subscription (push). The GraphQL queries guide covers fields, arguments, aliases, variables, fragments and directives.

L2: Mechanics

Steps 1, 3, 5 and 6 are in the Catalyst Center API Quick Start (page is 3.1.6 docs). The JSON key that holds the token in step 2 is not stated there. See footer.

Three mechanics decide most consume tasks:

  • Auth. Either exchange credentials for a token you resend in a header, or log in and let a cookie ride along. Catalyst Center uses Basic auth to get a token, then X-Auth-Token. APIC uses POST /api/aaaLogin.json with an aaaUser object carrying name and pwd, and returns an APIC-cookie (APIC REST API guide). Sessions expire; APIC has an aaaRefresh URI.
  • Async writes. Catalyst Center answers writes with a task response, so a 2xx on your POST does not mean the change is done. Poll the task, then read the object back.
  • Paging. Never assume one response is everything. See the table below.

L3: Exam detail

  • Variables, not string building. Declare $name: Type in the operation and pass values in the JSON variables object. Defaults go in the declaration. ! marks non-null.
  • Aliases let you call the same field twice with different arguments in one document. Fragments reuse a selection set. @include(if:) and @skip(if:) toggle fields from a Boolean variable.
  • Mutations are written like queries but with the mutation keyword; return the fields you want to confirm the change in the same call.
  • Introspection. __schema and __type(name:) let you discover types and fields (Introspection). It is often disabled in production, so the exam is more likely to hand you a schema or SDL than to rely on it.
  • Errors. In the Response page example, one deletion succeeds and the other returns null with an error at path ["secondShip"]. Your client must inspect errors every time.
  • Auth lives outside GraphQL. It is handled before the request is validated, typically as an HTTP header. Authorization happens in resolvers, field by field.

APIC detail worth knowing: the URL suffix .json or .xml is mandatory and sets the format; headers are ignored for that choice. The guide also lists a 90 second query timeout and a 100,000-object cap on generic class queries, and calls POST idempotent, which is stricter than the generic HTTP meaning. Those are APIC 4.2(x)-and-later docs; the lab APIC release is not stated by the task, so treat limits as ⚠ release-dependent.

Anatomy

Snippets are patterns from the docs above, not a drill solution. Assume Python 3.13 on the workstation; ⚠ unverified — test in lab that requests is installed (otherwise use urllib.request from the standard library).

# APIC: login, then class query with paging options (guide: aaaLogin.json, /api/class/..., page, page-size)
import requests
s = requests.Session(); s.verify = False   # sandbox cert; ⚠ lab only
s.post(f"{base}/api/aaaLogin.json",
       json={"aaaUser": {"attributes": {"name": user, "pwd": pw}}})
r = s.get(f"{base}/api/class/fvTenant.json", params={"page": 0, "page-size": 5})
for o in r.json()["imdata"]:
    print(o["fvTenant"]["attributes"]["name"])
print(r.json()["totalCount"])
# Catalyst Center: Basic auth for token, then X-Auth-Token (quick start)
t = requests.post(f"{cc}/dna/system/api/v1/auth/token", auth=(user, pw), verify=False)
token = t.json()["Token"]            # ⚠ key name not on the quick start page
h = {"X-Auth-Token": token}
requests.get(f"{cc}/dna/intent/api/v1/network-device/ip-address/{ip}", headers=h, verify=False)
# Meraki-style Link header paging (RFC 5988 rel=next, per Meraki pagination page)
url = first_url
while url:
    r = requests.get(url, headers=hdrs)
    rows += r.json()
    url = r.links.get("next", {}).get("url")   # requests parses Link into r.links
# GraphQL: variables in JSON, check errors every time
body = {"query": "query Q($id: ID!) { human(id: $id) { name } }",
        "operationName": "Q", "variables": {"id": "1000"}}
r = requests.post(gql_url, json=body, headers=hdrs)
j = r.json()
if "errors" in j: raise RuntimeError(j["errors"])

Speed notes

  • Read order for any new API doc: auth section, one GET example, one write example, then paging/limits. Copy the example's headers verbatim.
  • Offline discovery: curl -sk -i URL shows status, headers (including Link) and body together. Pipe bodies through python3 -m json.tool.
  • Ansible: ansible-doc cisco.aci.aci_rest shows its parameters and examples offline. The module takes path ending in .json or .xml, method get/post/delete, and content or src; its docs include a paging example with page_size (aci_rest). Lab collection is cisco.aci 2.12.0; the docs page does not show its own version.
  • GraphQL without a client library: build the JSON body with json.dumps and POST it. If the exam gives you a UI such as a GraphQL explorer, use it to confirm syntax, then port to Python.
  • ⚠ unverified — test in lab: whether jq is installed on the Candidate Workstation.

Micro-drill (~10 min)

Requirement. Using only the APIC REST docs and the DevNet Sandbox APIC, list the names of the first 5 tenants and report the total tenant count, then confirm the count by fetching with page-size large enough to return everything. Then, on paper, write the GraphQL request body that fetches human(id:"1000") name and height in feet using a variable for the id.

Reference. Path /api/class/fvTenant.json; options page, page-size; response keys imdata, totalCount; object path imdata[i].fvTenant.attributes.name. GraphQL body keys query, operationName, variables.

Target. DevNet Sandbox APIC (Part 1). Part 2 has no lab endpoint; it is a syntax exercise. ⚠ unverified — I did not confirm any GraphQL service in the lab or on a Cisco product.

Verify. Part 1: first call returns 5 names; totalCount equals the number of names in the large-page call. Part 2: your body has the three keys and no values pasted into the query string.

Hint

Login first and reuse the session. If the page-size call is capped, fetch in a loop with page until you collect totalCount items. For the GraphQL part, declare $id: ID! on the operation and use height(unit: FOOT) from the queries guide's example.

Recall check

Today

  1. Name the three things a Catalyst Center client must do between getting credentials and confirming a configuration change.
    AnswerGet a token via Basic auth, send it as X-Auth-Token, and for writes follow the task response then GET the object back.
  2. An APIC class query returns 5 objects but you expect more. Which two things do you check?
    AnswertotalCount versus the number of imdata items, and whether page/page-size were set (default behavior is not shown on today's pages).
  3. A GraphQL call returns HTTP 200 and data.field is null. Where do you look and why can the status be 200?
    AnswerThe errors array (message, path). Field errors give partial data alongside errors, and partial success can still be 2xx.
  4. What are the three keys in a GraphQL POST body, and which one is required?
    Answerquery (required), operationName (needed with multiple operations), variables.

  1. (2026-09-30) A looped task is registered as r. The next task uses when: r.stdout is search('x') and fails with an undefined attribute. Why, and what structure fixes it?
