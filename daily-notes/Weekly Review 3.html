2.7.c Variables and templating

1. Role has port: 80 in defaults/, 8080 in vars/, and group_vars sets 9090. What does the task see, and what does -e port=443 do?

The task sees 8080: role vars beat group_vars, and role defaults are the lowest rung. -e sits at the top and wins, so 443. ⚠ The type: key=value style extra vars normally arrive as strings; JSON/YAML-style -e keeps the type. Not stated on the fetched page.

2. set_fact: mode=a ran earlier; a later include_role passes mode: b. Which wins?

b. Role params (#20) and include params (#21) both rank above registered vars/set_fact (#19).

3. A template renders a blank line after each for-body and a leading space before interface lines. Which module defaults are involved, and what are two fixes?

trim_blocks defaults true and lstrip_blocks defaults false (template module page, verified 10-12). Fixes: set lstrip_blocks: true on the task, or put Jinja whitespace control ({%-) on the block tags. ⚠ The whitespace-control syntax was not re-fetched.

3.5.a-b Cadence vs on-change

4. update-policy periodic 30: what interval do you get, and what is the 17.5 minimum?

30 centiseconds = 0.3 s, not 30 s. The 17.5 guide gives a minimum of 100 (1 s), so the value is below the floor. ⚠ Whether the device rejects or clamps it on 17.16 is untested.

5. Name three limits of IOS XE on-change subscriptions.

Dampening must be 0; granularity is a row; not hierarchical (child containers are not seen, so subscribe to child lists separately); the XPath must point to a single object. Any three.

6. In gNMI, what do TARGET_DEFINED, SAMPLE with suppress_redundant, and heartbeat_interval each do?

TARGET_DEFINED lets the device choose on-change or sample per leaf. SAMPLE sends at sample_interval; suppress_redundant skips unchanged values. heartbeat_interval forces a send of an unchanged value after that time. From the OpenConfig gNMI spec read 10-13; the Cisco gNMI chapter has no subscribe-mode content. ⚠ IOS XE 17.5 ON_CHANGE support is unconfirmed.

1.5 App performance

7. A business transaction is slow but step 1 of the AppDynamics slow-response flow finds no slow snapshots. Where next?

⚠ Reconstructed. The flow continues through its later steps (database and remote-service calls, node/tier scope) and ends by asking whether most BTs are affected. The step pages failed to fetch on 10-14 and again today, so confirm the order in the product docs.

8. In a ThousandEyes HTTP server test, what does wait time measure and what does 0% availability mean?

Wait Time: how long the agent waits for the server to begin responding. 0% availability: no request in the round succeeded (no 2xx/3xx). ⚠ The doc lists Wait as a metric, not a phase; a "time to first byte" mapping is not on the page.

9. Path Viz shows a red ring mid-path vs on the destination node. What does each mean?

⚠ From the 10-14 page, not re-fetched today: a mid-path ring marks a problem at that hop, a destination ring marks the target itself. Re-read the Path Visualization page before relying on this.

2.6 Config from a source of truth

10. Payload passes pyang but the device returns 400. Name two URI vs body mismatches on a RESTCONF PUT to a list entry.

List key value in the URI differs from the key leaf in the body; the top-level node name or module prefix in the body does not match the resource addressed by the URI. ⚠ RFC 8040 PUT rule text was not read (fetch truncated).

11. Why does restconf_config with defaults fail on the second run of a create, and what makes it repeatable?

The default method is post, which creates, so the second run hits an existing resource. Use put (create or replace) or patch. ⚠ Exact error code on Cat8000V is untested.

12. netconf_config returns ok but show run is unchanged. Two causes? Also: confirmed-commit default and RESTCONF support?

Causes: edit went to the candidate and was never committed (commit: false), or a confirmed commit was not confirmed and rolled back; or default_operation: none with no per-element operation. Confirmed-commit default is 600 s and RESTCONF does not support it.

Integration drill (about 20 min)

Target: Cat8000V (lab IOS XE 17.16). Combines 2.7.c, 2.6, 3.5.a-b. No cisco.ios collection on the workstation.

Requirement: Build an Ansible role mdt_sub that pushes one configured periodic telemetry subscription via NETCONF, with the period coming from role defaults, overridable from group_vars, and a guard that skips the task when the period list is empty. Then prove the subscription is Valid and that a second run changes nothing.

  • Role variables: mdt_sub_id (int), mdt_period_cs (default 1000), mdt_xpath (string), mdt_receiver_ip, mdt_receiver_port.
  • Template: render the mdt-cfg payload from those variables; strip stray blank lines.
  • Task: ansible.netcommon.netconf_config with target, commit, lock, default_operation set deliberately.
  • Guard: a when: that evaluates to a real boolean on core 2.19.

Verify: show telemetry ietf subscription all then show telemetry ietf subscription <id> detail (state Valid); rerun the play and expect changed=0; change mdt_receiver_port and decide what must happen to the existing receiver (it cannot be modified in place).

Hint

Look up the namespace and leaf names with pyang -f tree on the Cisco-IOS-XE-mdt-cfg model, or YANG Suite. Check ansible-doc -t module ansible.netcommon.netconf_config for parameter defaults. A guard like when: mdt_period_cs | length on an integer is the kind of non-boolean 2.19 rejects; compare with mdt_period_cs | int >= 100.

Solution outline

defaults/main.yml holds mdt_period_cs: 1000; group_vars can override because role defaults are lowest. Template renders the subscription under the mdt-cfg container with the id, xpath, period, and receiver. Task uses target: auto (or candidate if enabled), commit: true, default_operation: merge, lock: always. Idempotence comes from merge semantics, so the second run reports no change. For a port change, delete the old receiver entry (operation="delete" or remove on that element) in one push and recreate it in another, or send both in order.

⚠ unverified — test in lab: mdt-cfg element names and namespace, whether 17.16 reports changed=0 on re-merge, and the delete-then-create ordering.
