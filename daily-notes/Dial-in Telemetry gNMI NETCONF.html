Mental snapshot

  • Dial-in means the collector connects to the router and asks for data. The subscription lives and dies with that session.
  • Two dial-in transports on IOS XE 17.5: NETCONF (establish-subscription, XML) and gNMI (Subscribe, JSON_IETF). Dial-out (gRPC, kvGPB) is tomorrow's cousin and is a different unit.
  • Dial-in subscriptions are "dynamic": nothing appears in running-config, IDs are assigned by the router, and a reload or switchover wipes them.
  • Two cadence choices: periodic (NETCONF period in centiseconds; gNMI SAMPLE with interval) or on-change. On-change has real restrictions on IOS XE.
  • Design questions you must answer: who initiates, what survives a reload, how many subscriptions (limit 100), what the collector can parse, how it authenticates.
  • NETCONF-YANG must be enabled for telemetry even if you only use gNMI.

Where this fits

Fundamentals to exam depth

L1: the concept

You already know SNMP polling and syslog push. Model-driven telemetry replaces both with a subscription: you name a YANG path and a cadence, and the device streams matching data. The only question this unit adds is who opens the TCP connection. If the collector does, it is dial-in. The Cisco chapter calls these dynamic subscriptions: created by the subscriber over RPC, tied to the session, and invisible in running-config.

Because the session carries the subscription, there is no persistence. If the router reloads or switches over, the collector must reconnect and subscribe again. The chapter says dynamic subscriptions need re-establishing after a stateful switchover. That is the main design cost of dial-in. The benefit is that the router needs no config per collector, and firewalls only need to allow inbound to the router.

L2: mechanics

NETCONF dial-in uses <establish-subscription> (RFC 8639 style) with stream yang-push, an XPath filter and either a period or a dampening period. The router replies ok and then pushes notifications on the same session. Cisco's chapter says establish and delete are the supported RPCs, and lists the notification:1.1 capability as a prerequisite in the hello.

gNMI dial-in is the same idea on gRPC. The client calls Subscribe with a SubscriptionList. The spec defines three modes: ONCE (send, then sync_response, then close), POLL (client asks for each round), and STREAM (long-lived). STREAM has three sub-modes. SAMPLE needs a sample interval in nanoseconds. ON_CHANGE sends on value change and can carry a heartbeat. TARGET_DEFINED lets the device pick per leaf, and it rejects a sample interval with InvalidArgument. Cisco's gNMI chapter only says Subscribe is supported and points to the telemetry chapter for detail, and that chapter lists gNMI as dial-in, yang-push, JSON_IETF.

Other restrictions from the chapter that decide designs: no subtree filters, no wildcard or range values in the XPath, maximum 100 subscriptions, no subscription QoS, no data-access authorization check. Predicate syntax for keys is [name="value"]. gNMI path flavors matter for the collector: RFC 7951 style uses module-qualified names, OpenConfig style does not, and legacy uses the module prefix.

The gNMI chapter's secure setup needs a trustpoint, gnxi secure-server, and optionally gnxi secure-client-auth. Credentials are passed as RPC metadata. Config changes made by gNMI Set persist across restart. Version note: the chapter is 17.5 and says gNMI 0.4.0; the lab runs 17.16, so confirm defaults on the box.

Micro-drill (~10 min)

Target: Cat8000V (17.5-era syntax; lab runs 17.16).

Requirement: Open a NETCONF session and create two dynamic subscriptions: one periodic every 30 seconds on memory statistics, one on-change on CDP neighbors. Prove both exist on the router, then remove the periodic one without touching the other.

Reference: stream yang-push; xpath-filter; period (centiseconds); dampening-period; XPath /memory-ios-xe-oper:memory-statistics/memory-statistic and /cdp-ios-xe-oper:cdp-neighbor-details/cdp-neighbor-detail (both appear in the 17.5 chapter).

Verify: show telemetry ietf subscription all lists two; detail shows type and filter; the first periodic update arrives immediately.

Hint

30 seconds is 3000 centiseconds. On-change uses dampening 0 and no period. Dynamic subscriptions die with the session, so keep the session open while you verify. Deleting by ID is a CLI clear, or delete-subscription in the session that owns it.

Recall check

Today's topic

  1. Why does a NETCONF dial-in subscription disappear after a switchover, and where would you see (or not see) it in the router config?
    Answer

    It is dynamic: created by RPC, bound to the session, assigned an ID by the router, not in running-config, not persisted. Re-establish after reload or switchover.

  2. You send an on-change subscription with dampening-period 60 and an XPath at a container holding many rows. Name two reasons it fails or misbehaves on IOS XE 17.5.
    Answer

    Dampening must be 0, and the XPath should select a single object; automatic hierarchy is not supported for on-change, and change resolution is a row.

  3. In gNMI, which stream sub-mode rejects a sample interval, and what does it do per leaf?
    Answer

    TARGET_DEFINED returns InvalidArgument if a sample interval is set; the target picks ON_CHANGE for events and SAMPLE for counters.

  4. Give the default insecure and secure gnxi ports and the command that shows server state.
    Answer

    50052 insecure, 9339 secure (per the 17.5 chapter); show gnxi state.

From history (2026-09-28)

  1. In a RESTCONF URI, where does the module-qualified name (e.g. Cisco-IOS-XE-native:) appear, and why is repeating it on nested containers wrong?
    Answer

    Only on the first (top-level) node of the data resource path after the root; children inherit the module namespace, so repeating it is only for a node from a different module.

  2. A YANG list node appears in a RESTCONF JSON body and in a NETCONF XML body. How does its shape differ between the two encodings?
    Answer

    JSON: an array of objects under the list name. XML: repeated sibling elements, one per entry, in the module namespace.
