2.3 REST and GraphQL

1. Catalyst Center: what happens between getting a token and confirming a config change?

Send the token in the X-Auth-Token header. PUT/POST/DELETE return a taskId and task URL. GET the task and check isError; false means success. The token comes from a POST to the auth endpoint with basic auth, under the key Token.

2. An APIC class query returns fewer objects than expected. What two parameters do you check?

page (starts at 0) and page-size. Each query builds a new result set, so unrequested pages can't be fetched later. Log record classes cap at 2,000 objects per page unless page=0 (5.2(3)+). ⚠ Default page size for non-log classes: not stated on the page; test on the sandbox APIC.

3. GraphQL returns HTTP 200 and data.field is null. Where do you look?

The errors array in the body. A field error during execution yields a partial response: other fields return values, the failed one is null, and both data and errors appear. The transport worked, so the status says nothing about field success. Request errors (syntax/validation) omit data.

3.4 Dial-out telemetry

4. You change the receiver port on a live subscription and the collector never sees it. Why, and what is the fix?

Receivers can't be modified. Delete the receiver and create a new one. Rewriting a receiver with identical settings forces a reconnect to a disconnected one. Configured subscriptions are removed only through configuration (no telemetry ietf subscription N), not RPCs.

5. What does update-policy periodic 30 do?

The period is in centiseconds (RFC 8641 and the IOS XE guide), so 30 means 0.3 s, not 30 s. The 17.5 guide's minimum is 100 (1 s). 30 s is 3000. ⚠ Whether 17.16 rejects 30 or accepts it: test in lab.

6. The subscription says Valid. Name the next three checks.

(1) Receiver state: is it connected, not connecting/disconnected (NETCONF get on Cisco-IOS-XE-mdt-oper mdt-subscriptions, per guide). (2) Reachability from the right VRF (source-vrf) and a listener on the receiver port. (3) Data actually arriving at the collector. "Valid" only means the device accepted the subscription; subtree filters make it invalid.

2.5 NETCONF XPath

7. An XPath filter returns success and empty data. Two likely causes?

Path/namespace/prefix doesn't match the model (wrong module or key), or the path is right and there's simply no matching data. Tell them apart by running the parent path with no key predicate and by checking the YANG model. ⚠ Prefix declaration behavior for plain get on IOS XE: RFC 6241 s8.9 was unreadable via the fetch tool; test in lab.

8. Where is XPath restricted in the guides?

IOS XE 17.5 telemetry guide: key names and values must be exact (no ranges/wildcards), union works only for NETCONF transport not gRPC, subtree filters unsupported (subscription goes invalid). NX-OS 9.3(x) NETCONF Agent chapter: XPath unsupported, subtree filter only (from the 10-07 fetch of that chapter, not re-fetched today).

9. Which Ansible module takes an XPath filter, and what must the device support?

ansible.netcommon.netconf_get (filter accepts XML, XPath, JSON or dict). The server must support the XPath capability or the call fails. Datastore via source: running/candidate/startup.

1.4 CI/CD troubleshooting

10. A push to an MR branch creates two pipelines. Cause and fix?

The config runs for both branches and merge requests. Adjust job rules, or add workflow:rules to switch from branch pipelines to MR pipelines once an MR is open.

11. Job can't reach tcp://docker:2375. What changed and what's the second error?

Docker-in-Docker 19.03+ starts with TLS automatically, so clients use 2376 with the certs (DOCKER_TLS_CERTDIR, DOCKER_HOST, DOCKER_TLS_VERIFY). If the host runs Docker Engine 20.10+ and the dind service is older than 20.10, builds fail with a cgroups mountpoint error. Use dind 20.10.x or newer.

12. You fixed the YAML but retrying the failed job fails the same way. Why?

⚠ Not stated on the debugging page fetched today. From general GitLab behavior, retrying a job reuses the pipeline's existing configuration; run a new pipeline to pick up the change. Verify on your GitLab instance. Where to look first: the debugging page's "Verify syntax" (pipeline editor / CI Lint) and "Verify job output" sections.

Integration drill (~25 min): NETCONF read-back gate for a telemetry change

Combines: 2.5 (XPath), 3.4 (dial-out subscription), 1.4 (CI triage), 2.3 (checking by API response, not by status code).

Requirement. On Cat8000V, a dial-out subscription streams memory-statistics every 60 s to a collector. A pipeline job must prove the subscription exists and its receiver is connected before reporting success. The job must also not run twice per push.

Reference (from this week's pages, ⚠ verify names on the box): subscription CLI telemetry ietf subscription, filter xpath, update-policy periodic (centiseconds), receiver ip address <ip> <port> protocol grpc-tcp; state read via Cisco-IOS-XE-mdt-oper mdt-subscriptions; Ansible ansible.netcommon.netconf_get with filter; GitLab workflow:rules.

Target. Cat8000V (NETCONF enabled with netconf-yang, port 830). No cisco.ios collection on the workstation; use netcommon modules only.

  1. Configure the subscription with a 60 s period (get the unit right) and a receiver in the management VRF.
  2. Write a play that runs netconf_get against the mdt-oper subscription data with an XPath filter narrowed to your subscription id, and asserts the receiver state.
  3. Add a pipeline with the job rules so it runs once per push whether or not an MR is open.
  4. Break it on purpose: change the period to 60 and see what the device reports.

Verify: show telemetry ietf subscription all detail shows Valid; the play's assert fails when the receiver is not connected; only one pipeline appears per push.

Hint

XPath keys must be exact: filter on the subscription id, not a wildcard. Check ansible-doc ansible.netcommon.netconf_get for how a namespace/prefix is passed. For the pipeline, the MR-vs-branch switch lives in workflow:rules.

Solution skeleton (⚠ unverified — test in lab) 
# IOS XE (Cat8000V)
telemetry ietf subscription 101
 encoding encode-kvgpb
 filter xpath /memory-ios-xe-oper:memory-statistics/memory-statistic
 stream yang-push
 update-policy periodic 6000
 source-vrf Mgmt-intf
 receiver ip address 10.28.35.45 57555 protocol grpc-tcp

# Play (names unverified)
- ansible.netcommon.netconf_get:
    source: running
    filter: "<your XPath to mdt-subscriptions entry with exact id>"
    display: json
  register: sub
- ansible.builtin.assert:
    that: "'connected' in (sub | to_json)"   # confirm real state string on the box

# .gitlab-ci.yml (rule shape, see MR troubleshooting page)
workflow:
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH && $CI_OPEN_MERGE_REQUESTS
      when: never
    - if: $CI_COMMIT_BRANCH

The first snippet follows the 17.5 guide's sample; the $CI_OPEN_MERGE_REQUESTS rule was not on today's fetched MR troubleshooting page, so test it. State string "connected" is a guess; the guide shows rcvr-state-connecting.
