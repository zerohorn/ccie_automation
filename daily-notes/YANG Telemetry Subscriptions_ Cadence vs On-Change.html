YANG Telemetry Subscriptions: Cadence vs On-Change

Date 2026-10-13Blueprint 3.5.a-bDomain 3 (Network Automation / telemetry)Tier 1 (gap)Read ~18 minUnit 10 of 49
3.5.a: identify YANG model elements and cadence for a subscription. 3.5.b: choose on-change vs event-driven delivery. Builds on 3.4 dial-in/dial-out; the transport is already done, this is the what and when.

Mental snapshot

  • A subscription = what (stream + XPath filter on a YANG node) + when (periodic or on-change) + where (receiver / session). Today is what and when.
  • Cadence is a property of the subscription, not of the data. A given IOS XE yang-push subscription is periodic or on-change, never both.
  • IOS XE periodic units are centiseconds: 1000 = 10 s, minimum 100 = 1 s, no default. NX-OS sample-interval is milliseconds. gNMI sample_interval is nanoseconds. Three platforms, three units.
  • On-change is a publisher capability per node, not a property of the model file. The Cisco guide says YANG itself does not mark it. You must ask the box.
  • "Event-driven" has two meanings here: on-change data pushes (yang-push) and notification streams (yang-notif-native, RFC 5277-style events). Know which one a task wants.
  • IOS XE on-change: dampening-period must be 0; granularity is a table row; not hierarchical.
  • Subscription state "Valid" proves syntax and support, not that data flows. Check receiver and collector next (3.5.f, later unit).

Where this fits

Fundamentals to exam depth

L1: concept

Polling asks the device "what is it now?" on your schedule. Subscriptions invert that: you tell the device which data and when, and it pushes. The "when" has two shapes. Periodic: send a full snapshot every N time units, regardless of change. On-change: send once at start (optionally), then only when something changes. Periodic costs steady bandwidth and gives regular time series (graphs, rates). On-change costs almost nothing when quiet and gives immediate edge detection (link down, neighbor change), but you lose a heartbeat unless you add one.

The "what" is a YANG node, addressed by an XPath filter. You find the XPath by walking the model (YANG Suite tree, or pyang -f tree). The model type matters: -oper modules hold state; -cfg hold config.

L2: mechanics (RFC 8639 / 8641 behind the CLI)

RFC 8639 defines the subscription machinery: streams, filters, dynamic subscriptions (created by RPC, tied to the session) and configured subscriptions (in config, survive reboot, valid / invalid / concluded). RFC 8641 adds the datastore stream "yang-push" with the two triggers: periodic (a period and optional anchor-time) and on-change (optional dampening-period, sync-on-start, and excluded change types). Periodic updates carry a full filtered snapshot (push-update). On-change updates carry only deltas as YANG Patch (push-change-update); a sync-on-start sends the initial full push-update.

RFC 8641 section 3.3 is explicit that a publisher may not support on-change for every object. It may reject the subscription, or accept and silently send updates only for supported parts; for configured subscriptions it may suspend. Section 3.10 notes that fast counters and similar nodes are poor on-change candidates and that clients need a way to discover support; no standard model existed then, so vendors provide their own. That is why IOS XE has the platform command below.

  • IOS XE on-change limits: not hierarchical (a filter on a container does not give you everything under it as on-change); change granularity is a row; unsupported data makes a dynamic subscription fail and a configured one go Invalid.
  • Union (|) in XPath works with NETCONF only, not gRPC, and not on yang-notif-native.
  • Configured gRPC dial-out: yang-push with kvGPB encoding only (per the 217427 article, tested on 17.3.3).
  • Configured on-change via mdt-cfg: the article sets the no-sync-on-start leaf to false. Read that literally and test it; the name reads inverted.
  • gNMI: SAMPLE has sample_interval, suppress_redundant (per leaf) and heartbeat_interval; TARGET_DEFINED rejects a client-set interval with InvalidArgument; ON_CHANGE sends current state first, then changes, with an optional heartbeat.
  • Event-driven as notifications: a stream like yang-notif-native carries YANG notification records (RFC 8639 streams), not datastore values. Pick it when the blueprint verb is "react to an event", pick yang-push on-change when it is "track a value".

Anatomy

Snippets pinned to IOS XE 17.5 guide syntax. The first is the guide's own periodic example; the second is the same shape as on-change (⚠ unverified — test in lab on 17.16).

! periodic: 6000 cs = 60 s
telemetry ietf subscription 101
  encoding encode-kvgpb
  filter xpath /memory-ios-xe-oper:memory-statistics/memory-statistic
  stream yang-push
  update-policy periodic 6000
  source-vrf Mgmt-intf
  receiver ip address 10.28.35.45 57555 protocol grpc-tcp

! on-change shape (no period; confirm accepted keyword form on 17.16)
telemetry ietf subscription 102
  encoding encode-kvgpb
  filter xpath /interfaces-ios-xe-oper:interfaces/interface
  stream yang-push
  update-policy on-change
  receiver ip address 10.28.35.45 57555 protocol grpc-tcp
show platform software ndbman switch active models   ! which models can do on-change
show telemetry ietf subscription all detail          ! state, filter, period/trigger
show telemetry ietf subscription 102 receiver        ! receiver state (wording varies)

Dynamic variant (dial-in, RFC 8639 establish-subscription): per the 217427 article you pick stream yang-push, the XPath filter, and the update trigger (period for periodic, dampening-period 0 for on-change). NX-OS contrast:

telemetry
  sensor-group 1
    data-source DME
    path sys/intf/phys-[eth1/1] depth 0
  destination-group 1
    ip address 10.0.0.5 port 50001 protocol gRPC encoding GPB
  subscription 1
    snsr-grp 1 sample-interval 0       ! 0 = event-based; 15000 = every 15 s
    dst-grp 1

Speed notes

  • Model browse offline: pyang -f tree -p <yang-dir> <module>.yang (⚠ unverified — test in lab: pyang and IOS XE model files on the workstation).
  • -oper in the module name = state data; start there for telemetry.
  • On the router: show telemetry ietf subscription ? and telemetry ietf subscription 1 then ? for each sub-command; the CLI help is the offline manual.
  • Remember one rule set: IOS XE cs, NX-OS ms, gNMI ns. Write the unit as a comment next to every interval you type.
  • NX-OS: show telemetry control database sensor-groups and show telemetry transport as first checks.

Micro-drill (~10 min)

Requirement. On Cat8000V, create two subscriptions to the same collector: (1) interface operational data every 30 s; (2) an on-change subscription for interface state. Show that the second is accepted and the first has the right period. Target: Cat8000V (17.16).

Reference. Module Cisco-IOS-XE-interfaces-oper (⚠ unverified — confirm module/prefix with YANG Suite or pyang); CLI telemetry ietf subscription; commands from the Anatomy section.

Verification. Both subscriptions show Valid in show telemetry ietf subscription all detail; period reads 3000 cs; the receiver is Connected; an shutdown / no shutdown on a spare loopback yields one on-change record.

HintConvert 30 s to centiseconds first. Find the exact XPath in the YANG tree (Properties: Xpath + Prefix); mind the leading slash.
Solution
telemetry ietf subscription 201
  encoding encode-kvgpb
  filter xpath /<prefix>:interfaces/interface      ! confirm prefix/path
  stream yang-push
  update-policy periodic 3000                  ! 30 s
  receiver ip address <collector> <port> protocol grpc-tcp
telemetry ietf subscription 202
  encoding encode-kvgpb
  filter xpath /<prefix>:interfaces/interface
  stream yang-push
  update-policy on-change
  receiver ip address <collector> <port> protocol grpc-tcp

If 202 goes Invalid, the node isn't on-change capable: check the ndbman models output, then pick a supported list.

Recall check

Today

1. A subscription uses update-policy periodic 30. What interval do you get, and what is the minimum allowed on IOS XE 17.5?30 centiseconds = 0.3 s, which is below the minimum of 100 cs (1 s). Expect rejection or an invalid subscription; 3000 gives 30 s.
2. Name three limits of IOS XE on-change subscriptions.Dampening must be 0; not hierarchical with row granularity; unsupported data makes dynamic fail and configured Invalid. Also: no wildcard/range/subtree XPath.
3. How do you learn which IOS XE models support on-change, and why can't you read it from the YANG?show platform software ndbman switch active models. The guide says YANG models carry no indication of on-change support (RFC 8641 s3.10 says the same gap exists and vendors fill it).
4. In gNMI, what do TARGET_DEFINED, SAMPLE with suppress_redundant, and heartbeat_interval each do?TARGET_DEFINED: target picks ON_CHANGE or SAMPLE per leaf and a client interval should be rejected. suppress_redundant: skip unchanged leaves. heartbeat_interval: force one update per interval even if unchanged.

5. (2026-10-06) A subscription shows Valid. List the next three checks before calling it working.Receiver state is Connected; collector is listening and reachable (port, firewall, VRF source); records are actually arriving and decoding at the collector.
